# Архивы во вложениях

Реализация гибридной обработки находится под `ATTACHMENT_REVIEW_ENABLED`.
Сохранённый состав обработки выполняется независимо от последующего выключения флага.
ZIP, 7z и RAR относятся к вложенным контейнерам; список корневых upload-форматов не расширяется.

ZIP использует стандартный zipfile, 7z — py7zr 1.1.4, RAR metadata — rarfile 4.5.
RAR extraction выполняет явно настроенный `ARCHIVE_7ZIP_PATH` (абсолютный путь),
либо установленный системный 7-Zip. Наличие RAR codec проверяется реальным чтением RAR3/RAR5,
а не только запуском команды help. Не использовать helper из каталога загруженных файлов.

Пароли, многотомные архивы и выполнение SFX не поддерживаются. Такие ветки имеют явный
статус в дереве и не выдаются за успешно обработанные. Solid-архив может требовать
декодирования предшествующих файлов; исключение гарантирует отсутствие parsing/indexing
их содержимого, но не обещает нулевое время распаковки.

Политика и общие лимиты: [ТЗ](superpowers/specs/2026-10-17-hybrid-attachment-processing-design.md).

## Предпросмотр Excel перед выбором

В окне состава обработки рядом с сохранённым XLSX доступен «Предпросмотр»,
в том числе для исключённого файла из вложенного письма или ZIP/7z/RAR.
Предпросмотр читает оригинал текущего review, показывает список листов и первые
30 непустых строк выбранного листа в столбцах A–T, до 500 символов на ячейку.
Ограничение фрагмента отображается явно; форматирование и объединение ячеек не воспроизводятся.
Формулы показываются сохранённым значением или буквальным текстом, ссылки не открываются.
Постоянное предупреждение объясняет сырые значения: даты могут быть числами,
проценты — долями, ведущие нули могут отсутствовать, boolean показаны как 0/1;
сохранённые результаты формул могут быть устаревшими. Это предупреждение не связано с усечением выборки.

Это отдельный JSON GET `/api/documents/{doc_id}/processing-scope/attachments/{source_key}/preview`
с `review_id` и индексом `sheet`. Он требует обычной авторизации, проверяет документ,
актуальный review и SHA-256 сохранённого payload; ответ имеет `Cache-Control: no-store`.
После копирования оригинала под document lock разбор идёт в штатном parser supervisor
с общими slots и лимитом времени до 10 секунд. Вход ограничен 50 МиБ, XML-фрагменты —
16 МиБ суммарно, workbook metadata — двумя чтениями до 1 МиБ, список листов — 256.
Достижение лимита фрагмента сохраняет уже прочитанные данные и отмечает неполноту.
Просмотр не создаёт чанки/концепты/индекс, не меняет review и не скачивает файл в браузер.
Кнопка включения/исключения меняет только текущий выбор в окне; сохранение и запуск остаются явными.
Перед раскрытием неизвестной ветки изменённые галочки сохраняются через CAS.
Конфликт или обычная ошибка сохранения сохраняют локальный выбор. При обновлении
устаревшего review из предпросмотра изменения переносятся для сохранившихся ключей.
Отдельной кнопки «Обновить данные» в редакторе нет. Первый вход открывает просмотр
опубликованного состава; сохранённый draft открывается по «Редактировать вложения».
Таймаут запроса или потеря edit lease возвращают в просмотр. Перед повторным Edit
читается серверное состояние; сохранение и применение автоматически не повторяются.

Одновременно выполняется один запрос предпросмотра на документ в открытом интерфейсе:
быстрые переключения объединяются до последнего выбранного листа. Закрытие окна
не выдаётся за отмену server worker; повторное открытие того же оригинала присоединяется
к ещё выполняющемуся запросу. Результаты после завершения не кэшируются.
При 409 предлагается обновить состав, а не повторять запрос к устаревшему review.
Windows bootstrap не импортирует диагностику/LLM-клиенты в дочерний процесс до
worker admission; resource limits и общий parser semaphore сохраняются.

## Оригиналы и рекомендации после публикации

Уже извлечённые в review исключённые originals копируются в отдельный каталог
кандидата с проверкой SHA-256, путей и общего бюджета. Они регистрируются как
скачиваемые источники без разбора/индексации содержимого. Замена и очистка review
не удаляют оригинал активного поколения; последующая генерация может взять его из
опубликованного источника. Никогда не извлекавшиеся потомки остаются `container_only`.

Автоматические рекомендации сохраняются отдельно в `inventory.recommendations`:
ручной Save не стирает `heavy/aggregate_budget`. Summary возвращает
`recommended_excluded_count`; у legacy JSON без рекомендаций значение неизвестно.
Дополнительная SQL-миграция для этих JSON-полей не требуется.

## Ограничения контейнеров

Adapters не пишут по архивным именам: вывод идёт в управляемый sink. Пути с traversal,
drive/UNC/ADS, ссылки, специальные файлы и дубли нормализованных имён отвергаются.
Helper запускается без shell и без stdin, с закрытым stderr; внешний supervisor
ограничивает весь process tree, время и память.

Проверка codecs (из окружения приложения, без БД):

```powershell
python backend/scripts/check_archive_runtime.py --helper 'C:/Program Files/7-Zip/7z.exe' small.zip small.7z small.rar
```

Команда читает содержимое и печатает SHA-256 каждого файла. В отчёте приёмки отдельно
фиксируются Windows и конечный Linux-образ. Поддержка macOS заявляется только после
такого же форматного и process-tree smoke. Runtime не скачивает и не обновляет инструменты.


## Миграция и включение

1. Согласовать отдельное окно внедрения. Остановить writers/очередь; сохранить согласованный backup PostgreSQL/SQLite, uploads/bundles и Qdrant. Проверить восстановление в новом каталоге/project. Текущую генерацию не отменять ради inspect.
2. На копии выяснить `alembic current`, graph/head и фактические таблицы/колонки/constraints. `create_all` не добавляет колонки, а старый Alembic marker не доказывает их отсутствие. Не выполнять автоматический stamp или массовый ручной ALTER. Для обнаруженного drift подготовить отдельное сверенное восстановление истории/схемы.
3. На согласованной копии с корректной историей062 выполнить migration063 (`063b1c2d3e4f`), сверить schema drift, legacy reads и новый upload. Отдельно проверить SQLite и используемую версию PostgreSQL. Проверенная здесь ephemeral PostgreSQL17 не заменяет копию рабочей БД.
4. Развернуть совместимый backend/frontend с `ATTACHMENT_REVIEW_ENABLED=false`, до запуска приложения обновить схему. Флаг не отключает наличие новых ORM-колонок. Проверить списки, старые документы и поиск.
5. В конечном образе, под штатным UID, выполнить `check_archive_runtime.py` на ZIP,7z, compressed/solid RAR3/RAR5. Проверить configured absolute helper, notices/SBOM, time/memory/process-tree isolation; не заменять codec smoke командой `--help`.
6. Включить флаг для согласованной приёмки: root+mail+archive+heavy/light Excel. Убедиться, что до confirm нет LLM/embed/index работы; затем проверить исключённый термин в SQL/search/sources, original download, active/pending и cancel. Проверить целевые роли/SSO.
7. Сравнить задержки и RSS с отчётом; feature flag включать штатно после целевой приёмки. Уже готовые документы автоматически не перегенерируются. Для текущего проблемного документа отдельно открыть состав и согласовать новый запуск.

Миграция additive063: `document_processing_reviews`, nullable scope/signature/staging fields и уникальный scope request ID. Старый snapshotNULL читается как `legacy_all`. Downgrade разрешён только без сохранённых reviews/policies; при их наличии он явно отказывает, чтобы не потерять пользовательский выбор.

Быстрый rollback — выключить флаг в совместимой версии: новые legacy-случаи идут прежним путём, уже сохранённые scope продолжают исполняться. Это не удаляет scope и не отменяет миграцию. Возврат к старому несовместимому binary допустим только как согласованное восстановление согласованных БД/FS/Qdrant backup; иначе повторная обработка может вернуть исключённые вложения.

Диагностика без БД/LLM/индекса:

```powershell
python backend/scripts/inspect_attachment_scope.py --help
python backend/test_scripts/probe_attachment_scope.py --help
```

Inspect пишет только явно заданный отчёт и проверяет SHA исходника до/после. Файлы отчёта могут содержать имена вложений: хранить их как внутренние артефакты документа. [Локальная приёмка](acceptance/2026-10-17-hybrid-attachments.md).

# Маркировка из просмотра документа — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for implementation in this chat, or superpowers:subagent-driven-development if the user selects delegated execution. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Пользователь открывает найденный документ или фрагмент, исправляет маркировку в диалоге и продолжает чтение на прежнем месте.

**Architecture:** Общая клиентская кнопка открывает новый диалог на четырёх существующих страницах просмотра. Диалог переиспользует редакторы и действующие API тегов, разработки и языка; состояние формы отделено от подтверждённого сервером документа. Серверные страницы и компоненты содержимого сохраняют текущую структуру.

**Tech Stack:** Next.js 16 App Router, React 19, существующие CSS и i18n, Node.js test runner; FastAPI API без изменения контрактов.

**Spec:** Согласованный в чате 01.10.2026 вариант: кнопка «Маркировка», текущие теги/разработка/язык документа, сохранение места чтения, существующие права. Пользователь утвердил реализацию словом «делай». Реализовано в текущем чате; фактическая приёмка записана ниже.

## Global Constraints

- Редактируется документ по `docId`, включая переходы на его концепт, чанк или вложенный источник. Вложение не становится отдельным объектом маркировки.
- Доступность кнопки как в `DocumentList`: `mode === "disabled" || hasRole("editor", "admin")`; неизвестный режим не даёт доступ. Серверные проверки прав остаются действующими.
- Никаких новых зависимостей, миграций, изменений ранжирования, перегенерации документов или новых API записи. Используется штатная синхронизация метаданных с поисковым индексом.
- Все строки в ru/en, затем генерация обоих backend i18n-манифестов. `canonicalLocale` тегов и `source_locale` документа — разные поля.
- Существующие формы списка документов сохраняют поведение; изменение общих контролов ограничено совместимостью с диалогом.
- До коммита обязателен `node scripts/check-project.mjs`; commit/push не входят в текущий запрос на планирование.

## Review Focus

1. Тег с номером разработки изменяет привязку через `document_tag_service._reconcile_development`: явный выбор разработки в форме должен применяться после тегов (задача 1).
2. Частичный успех или потеря ответа: нельзя сообщать об общем успехе, отменять уже сохранённое либо повторять подтверждённые операции без необходимости (задача 1).
3. Выпадающие списки сейчас портируются в `document.body`, а `Modal` ограничивает фокус своим DOM: выбор, Tab и Escape должны работать внутри диалога (задача 2).
4. Удалённая/недоступная разработка, пустой справочник, неизвестный язык: текущее значение не подменяется пустым и не очищается при сохранении другого поля (задачи 1–2).
5. Переход из поиска с `?concept=`, подсветкой, раскрытой таблицей и прокруткой: открытие и закрытие диалога не сбрасывает просмотр (задача 3).

## Поведение диалога

- Кнопка «Маркировка» в панели действий. Заголовок диалога и имя исходного документа явно показывают объект изменения.
- На каждом открытии загрузить свежий документ, разработки и активные языки. До загрузки документа сохранение недоступно; ошибка показывает «Повторить». Ошибка справочника не превращается в пустой успешный результат; соответствующее поле заблокировано до повторной загрузки.
- Поля: теги (`TagPicker`), язык новых тегов (`ReferenceLocaleSelect`), разработка (`DevelopmentPicker`), язык документа (`SearchableSelect` + `buildLocaleOptions`). Неприсутствующая в справочнике текущая разработка отображается по данным документа, без создания фиктивной записи справочника.
- Изменения локальные до кнопки «Сохранить». «Отмена», Escape и закрытие по фону до сохранения отбрасывают черновик. Enter при выборе тега не отправляет форму.
- Во время сохранения запретить повторное сохранение, изменение полей и закрытие. При полном успехе закрыть диалог и показать уведомление; повторное открытие читает актуальные данные.
- Не вызывать навигацию, reload или `router.refresh()` после сохранения: содержимое и место чтения сохраняются. Обновить словарь тегов через `bumpTagVersion()` после успешной записи тегов.
- Ошибки через `friendlyApiError`, без внутренних подробностей. При частичном успехе показать сохранённые поля, оставить диалог открытым с несохранёнными значениями; вместо обещания отменить всё использовать кнопку «Закрыть».
- `dev_tags_sync_pending` и `source_locale_sync_pending` — сохранённые изменения с предупреждением об обновлении поиска. Не обещать мгновенное изменение существующей выдачи: теги также синхронизируются фоново.

Ответ с sync-pending считается применённым и сохраняет предупреждение даже при последующей ошибке.

- [x] При ошибке записи диалог перечитывает документ перед повтором: ответ мог потеряться после сохранения. Если чтение тоже не удалось, повторная запись блокируется до успешного «Повторить». ## Поставка и откат

Порядок: helper сохранения → диалог и контролы → подключение страниц → приёмка. Рекомендуется реализация последовательно в текущем чате: задачи зависят от одного контракта сохранения, распределение между исполнителями здесь мало помогает.

Откат функции — вернуть изменения фронтенда и соответствующие i18n-манифесты целевым revert после коммита. Сохранённые пользователями теги, разработки и языки остаются обычными данными и автоматически не откатываются. Нового состояния БД или миграции для отката нет.

## Границы

Существующие API сохраняют три поля отдельными запросами; общей транзакции у диалога нет. Это отражено в обработке частичного успеха. Конкурентное редактирование одного и того же поля сохраняет существующую семантику последней записи; UI отправляет только изменённые поля и каждый раз перечитывает документ при открытии. Новая блокировка версий и атомарный endpoint — отдельная задача при необходимости.

Браузер: переход из поиска AUTHORITY-CHECK к концепту, диалог на всех четырёх страницах, обе ветки `?concept=`, неизменные URL и подсветка после закрытия; сохранение тегов/разработки/языка с повторным чтением на отдельной тестовой записи; отмена, клавиатура, Escape по уровням, возврат фокуса, мобильная ширина 390 px. Независимое ревью выявило две проблемы: восстановление после ручного повторного GET и активацию пункта языка клавишей Enter. Обе воспроизведены и исправлены; добавлены четыре теста восстановления, повторная браузерная проверка Enter успешна.

Тестовые значения отдельного документа восстановлены, тестовая запись перемещена в корзину. Маркировка пользовательских документов корпуса не изменялась. Изолированные серверы остановлены. Commit/push не выполнялись.

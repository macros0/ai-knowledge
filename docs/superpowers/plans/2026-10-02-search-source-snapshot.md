## Решения

- Реализация выполнена inline в managed worktree от текущего HEAD; зависимости
  используются из существующего backend/.venv. Новой установки пакетов нет.
- PostgreSQL SELECT FOR SHARE сохраняется. Transaction read-only запрещает даже
  такие блокировки, поэтому probe запрещает SQL-записи через SQLAlchemy event.
- Before/after использует исходную `_enrich_retrieval_hits_in_session` из
  неизменяемого Git commit; остальные стадии общие. Это измерение именно изменения
  hydration, а не сравнение двух различных полных релизов.
- Пять наблюдений не дают p95. Из-за вариативности неизменённых Qdrant-вызовов
  два глубоких сценария повторяются на 30 чередующихся парах без фоновых тестов.
- Итоговая проверка ограничена согласованными файлами регрессий поискового пути:
  172 passed. Полный backend-прогон запущен, но остановлен как чрезмерно широкий
  для изменения; его незавершённость явно сохранена в отчёте.
- Полнота sources остаётся независимой от лимита контекста LLM. Остановка widening,
  sparse веса, число кандидатов и длина текста до exact matching не изменяются.

## Приёмка и откат

Один SELECT DocumentSource на hydration; совпадение полных digest выдачи и
снимков; корректный отказ при смене поколения/удалении и корректность mail_mode.
Сравнивать median/p95 при одинаковом корпусе; не заявлять универсальный процент
ускорения по шумной короткой серии. Изменение не требует миграции или переиндексации.
Откат — вернуть два изменённых service-файла. Подробности в отчёте
`../reports/2026-10-02-search-source-snapshot.md`.

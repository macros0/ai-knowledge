# Улучшения UX проекта — Implementation Plan

> **For agentic workers:** использовать `superpowers:executing-plans` для последовательной реализации после согласования плана. Способ исполнения выбирается при переходе к реализации; этот документ не запускает работу агентов.

**Goal:** сделать работу с документами и поиском понятнее, сохранить пользовательский контекст при переходах и дать явное восстановление после ошибок.

**Architecture:** три независимо принимаемых этапа: локальные исправления существующих экранов; перенос клиентской загрузки в общий контекст приложения; упрощение фильтров и представления источников. Существующие API, поиск и серверная обработка документов сохраняются. Новые пользовательские состояния вводятся в React, а детерминированная логика проверяется средствами `node:test`.

**Tech Stack:** Next.js App Router, React, JavaScript, существующие RU/EN-словари, CSS и `node:test`. Новые библиотеки для первого этапа не нужны.

**Spec:** UX-аудит и решения этого плана от 06.10.2026; исполнение утверждено пользователем сообщением «приступай».

**Статус:** реализация T1–T8 разрешена сообщением «приступай» и выполнена в worktree `codex/project-ux-improvements` и по запросу пользователя перенесена в рабочую копию `main`. Автоматические проверки и синтетические браузерные сценарии завершены; реальная production-приёмка и отдельные ручные ворота остаются OPEN. Подробности: [отчёт](../reports/2026-10-06-project-ux-acceptance.md). Незакрытые пункты ниже сохраняют дополнительные требования проверки, а не обозначают отсутствие реализации.

## Проектные решения

Основные сценарии: загрузить пакет документов и понять результат; задать вопрос и исправить его после сбоя; проверить источник, не потеряв вопрос и ответ; вернуться к прошлой переписке.

Рассмотрены три подхода:

1. **Поэтапные изменения — рекомендуется.** Исправить конкретные разрывы сценариев, затем принять устойчивую загрузку и новую компоновку чата отдельно. Каждая часть проверяется и откатывается независимо.
2. Только небольшие правки текста и внешнего вида. Быстрее, но не решает прерывание загрузки и потерю черновика.
3. Полная перестройка интерфейса. Затрагивает сразу все сценарии и затрудняет определение причин регрессий; для выявленных проблем не требуется.

Предлагается сохранить существующую структуру разделов. Поле вопроса становится многострочным; активная область поиска видна в компактной строке. Источники группируются по документам, но каждый найденный фрагмент остаётся доступен. Пакетная загрузка продолжает работу при клиентских переходах между разделами в той же вкладке браузера.

## Global Constraints

- Реализация разрешена пользователем после подготовки плана; коммит, push и развёртывание не разрешены.
- Не менять retrieval/ranking, top_k, лимиты контекста LLM и серверные права ради упрощения UI. Полный найденный набор источников доступен независимо от включения в контекст модели.
- `score` остаётся совместимым полем API; меняется пользовательское представление, а не оценка и порядок результатов.
- Сохранить вкладки «Документы → Загрузить документы → Корзина». Корзина справа. Размещение и текст `DocumentQueueStatus` не менять.
- Сохранить фильтры документов при навигации, приоритет явного URL, выбор документов, существующие проверки похожих файлов и различие resume/regenerate.
- Новые тексты сразу в RU/EN. Не выдавать техническую оценку поиска за вероятность правильного ответа; не раскрывать traceback или секреты.
- Владельцем черновика и пакета является текущий пользователь. При выходе/смене пользователя очищать приватное клиентское состояние и игнорировать запоздалые результаты старого владельца.
- Черновики и объекты File хранить в памяти приложения. Восстановление после перезапуска браузера, offline-очередь, Service Worker и серверная загрузка частями не входят в план.
- Не обещать продолжение передачи файлов после закрытия/обновления вкладки. Предупреждать о незавершённой передаче при уходе из документа браузера там, где браузер поддерживает такое предупреждение.
- Не добавлять сторонний UI/test framework без подтверждённой необходимости. Перед изменением кода читать локальные руководства Next.js согласно `frontend/AGENTS.md`.
- Чужие изменения в общем checkout сохранить. Коммит, push и развёртывание не входят в этот запрос.

# Изолированный контур измерений этапа 8

Дата создания: 12.09.2026.

Для корпусной приёмки создан отдельный локальный контур, в который должны
попадать только документы и записи глоссария, содержание которых пользователь
может предметно подтвердить.

| Компонент | Тестовое значение |
|---|---|
| PostgreSQL database | `okf_stage8_test` |
| Qdrant collection | `okf_knowledge_stage8_test` |
| файловое хранилище | `tests/tmp/stage8-data` |
| начальное состояние | 0 документов, пустая коллекция |
| feature flag | `GLOSSARY_QUERY_EXPANSION_ENABLED=true` |

Текущие база `okf_knowledge`/коллекция `okf_knowledge_base_v2` и каталог `data`
не изменялись. Frontend остаётся доступен по адресу `http://localhost:16300`,
но backend сейчас подключён к тестовому контуру. Из-за новой auth-схемы БД при
первом входе в этот контур может потребоваться заново пройти Keycloak.

Для возврата к прежнему контуру выполнить из корня проекта:

```powershell
.\scripts\start-all.ps1
```

Это не удаляет тестовую БД или её файлы; команда лишь возвращает backend к
значениям из `.env`.

Для запуска именно измерительного контура в дальнейшем достаточно выполнить:

```cmd
tests\scripts\stage8\start-stage8-test.cmd
```

CMD проверен реальным запуском: общий стек поднят, backend переключён на
`okf_stage8_test`, а `/health` вернул `ok` по всем зависимостям.

Для запуска измерительного Python-скрипта с теми же настройками используется
общий runner:

```cmd
tests\scripts\stage8\run-stage8-test.cmd backend\test_scripts\stage8_manifest.py --output ..\tests\tmp\stage8-data\stage8-manifest.json
```

Runner временно передаёт дочернему процессу `DATABASE_URL`, `DATA_DIR`, имя
коллекции, флаг глоссария и `KNOWLEDGE_PROFILE`, поэтому измерительный скрипт
не может случайно прочитать основную БД из `.env`. Запуск `--help` и генерация
manifest проверены; исходный manifest показал пустую тестовую БД и
`labels.approved=false`.

Перед загрузкой документов можно выполнить лёгкий read-only preflight:

```cmd
tests\scripts\stage8\check-stage8-test.cmd
```

Он проверяет `/health` работающего backend и сравнивает фактический
`knowledge_profile` с профилем Stage 8; при ошибке или запуске основной базы
команда завершается с ошибкой до загрузки документов.

В preflight учтена особенность Windows PowerShell 5.1: ответ `/health` с
кириллическим профилем принудительно декодируется как UTF-8. До исправления
это давало ложное несовпадение профиля (`ÐÐ·Ð¼ÐµÑ...`) и блокировало корректный
контур. Повторный реальный запуск `check-stage8-test.cmd` прошёл с фактическим
профилем `Измерительная база Stage 8` и четырьмя зависимостями `ok`.

В интерфейсе активный контур показывается статусным бейджем «Измерительная
база Stage 8», а второй строкой — состояние «Глоссарий: включён/выключен».
Источник обоих значений — `/api/settings`, а не захардкоженная надпись; для
основного контура используется `KNOWLEDGE_PROFILE=Основной контур`. Это
снижает риск загрузить документы не в ту базу или принять выключенный
глоссарий за работающий, но не заменяет проверку адреса/профиля перед
массовой загрузкой.

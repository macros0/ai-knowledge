## Реализовано

- `table_classification` — строгий объект из четырёх полей, без списка колонок. Канонический файл промпта и встроенный fallback синхронизированы. Использует classification budget, включая standard-профиль. Старый `classification` совместим; строгие массивы генерации и проверки truncation/trailing JSON сохранены.
- Допустимость `title_col` проверяется по исходной шапке. Невалидные/null/string/bool индексы дают явный fallback. Короткая строка с отсутствующей ячейкой названия сохраняет все имеющиеся значения и получает название `?`, без подстановки другой колонки.
- Кэш версии 2 включает модель, prompt hash, task и весь отправленный preview. Старые записи глобально не удаляются; legacy `description_cols` остаётся внутренним совместимым полем.
- Физические повторные строки и одинаковые whole-таблицы сохраняют отдельные source spans. Сохраняется детерминированный маршрут больших справочников.
- `table-quality.json` сохраняется в каталоге поколения перед publication manifest, включая режим без Markdown-бандлов. Manifest проверяет SHA-256; потерянный/изменённый отчёт не публикуется поверх прежней активной версии.
- Отчёт содержит только locator legacy source/chunk/table, метод, безопасный код причины, counts и header status. Тексты ячеек и исключения провайдера исключены. Измеряются только доступные Markdown-строки; исходные ячейки и корректность шапки остаются неизвестными. Реальная неполнота приоритетнее fallback warning; старое предупреждение не снимается по одному row count.
- Read-only `probe_tables.py`: parse/retrieval/compare, независимый OOXML inventory, gates по координатам/типизированным значениям. Scope учитывает документ; пустые/переупорядоченные листы сохраняют идентичность. Compare отдельно показывает отсутствие регрессии и принятие исходного эталона, сохраняя failed/unknown gates.

## Baseline T0 и оставшиеся границы

Оригинал A заморожен SHA-256. Локально сохранены 147 418 заполненных исходных ячеек на 10 листах; OOXML дополнительно содержит 156 записей без значения/кэша. Заморожены 40 запросов: 20 таблицы, 10 проза, 5 замечания, 5 вложения/mail. Evidence для нетабличных вопросов фиксирован из канонических источников, а не из нового ответа модели.

Сравнение исходных значений с Markdown-проекцией дало **303 отличия, все — внешние пробелы**, и **две отличающиеся legacy-шапки**. Исходные строки не объявляются потерянными по этим отличиям. Правильность сложной шапки остаётся **unknown**; независимая семантическая приёмка шапок нужна до принятия R2.

Поиск: обязательный источник дошёл до кандидатов для **38/40**, значение+источник до финального контекста для **29/40**; все **11 неуспехов** сохранены. Однократная матрица 40 различных вопросов: median около 66 мс, p95 около 106 мс. Это baseline данного прогона, не performance acceptance T9. Counts: 11 414 канонических концептов, 397 чанков, 11 805 Qdrant points; объём uploads около 484 МБ. Точность финальных ответов, фактические generation tokens и peak generation RSS **не измерены**, значения `null` сохранены.

## Решения и ограничения review

1. Старые ожидания «null → колонка 0» и дедуп физически одинаковых строк/таблиц заменены требованиями строгого fallback и сохранения происхождения. Возможен рост числа повторных концептов; неверный провайдер явно использует резервный метод.
2. Входной preview остаётся пятью полными строками. Ограничения 12 колонок × 3 строки, cell/text/token budgets относятся к T6. Проверенный край review: input 80 154 символа всё ещё возможен; R1 исправляет рост ответа, а не входное переполнение.
3. Шапки/типы/формулы/структурные ссылки, исправление 11 retrieval failures и массовая миграция — R2. Unknown и failed baseline не превращаются в зелёную приёмку.
4. DB-only persistence и hash inclusion проверены исполнением; tamper fault injection исполнен с dual-write bundle, общий verifier не имеет ветки по режиму bundle. Отдельный DB-only tamper-тест не заявляется выполненным.
5. Неизмеренные answer/token/RSS metrics остаются неизвестными. Два сбоя полного backend исправлены и проверены повторными модульными прогонами; единого зелёного полного прогона после последних двух правок не заявляется. Независимый review и его шесть исправлений подтверждены отдельно.
6. Пользователь выбрал существующую `main`. Commit/push/deploy по плану требуют отдельной команды; посторонняя Kubernetes-документация сохранена. Публикации/перегенерации рабочего корпуса не было.

Подробный manifest, оригинальные значения, probe-ответы и полные журналы — только в игнорируемом `data/table-eval/`. В Git предназначены лишь код, синтетические fixtures и этот обезличенный отчёт. Отсутствующий отчёт старого документа не переоценивается задним числом.

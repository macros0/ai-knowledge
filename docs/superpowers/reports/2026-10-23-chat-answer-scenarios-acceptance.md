# Приёмка сценариев ответа

Дата: 23.10.2026. Ветка: `codex/chat-answer-scenarios`, исходная версия `ba8cd2a51190536a837ee46f1335f060bb3c64b6`.
Статус: реализация и локальная приёмка завершены. Полный backend и обязательный gate прошли. Публикация, слияние и миграция рабочей БД не выполнялись.

## Что реализовано

Верхний режим «По сценарию», выбор личного или общего сценария, каталог с поиском и страницами, редактор, независимый пробный ответ и личная копия. Автор меняет свой сценарий; по уточнению пользователя администратор также может редактировать и удалять чужой общий сценарий. Чужие личные в каталоге администратору недоступны. Новая сохранённая версия применяется к следующему запросу; принятый запрос сохраняет неизменяемые название, версию и инструкции. Снимок читается после удаления или снятия публикации. Для чужого общего сценария доступен просмотр и копирование.

Сценарий использует существующий полный механизм ответа. С выбранными источниками новый поиск не выполняется. Ограничения источников и обязательные правила достоверности сохранены. Авторство обрабатывает существующий защищённый механизм с явной меткой. Preview не сохраняет сообщения или каталог, использует общий лимит и отдельную отмену.

Две новые SQL-таблицы, Alembic `068b1c2d3e4f`, отдельный идемпотентный companion `backend/scripts/migrate_answer_scenarios.py` с dry-run по умолчанию. Он не продвигает общую Alembic-версию старой dev-БД. `CHAT_SCENARIOS_ENABLED=false` запрещает новые сценарные операции, оставляя старые снимки читаемыми. При отключённой аутентификации функция недоступна.

## Реальная модель и браузер

Изолированный стенд: backend `127.0.0.1:18010`, production frontend `127.0.0.1:16310`, синтетические материалы о коде подразделения и дате заявки. Рабочая БД и основной стек не изменены. Для воспроизводимой проверки поиска подставлялась фиксированная доступная выборка; генерация выполнялась реальной настроенной Qwen3.6-35B-A3B-UD-Q6_K_XL.

Обычный полный ответ на том же синтетическом источнике проверен отдельно: 15.34 с, все три требования и [1], без метаданных сценария.

Подтверждены: таблица проверок, сохранение v1, обновление до v2 и автоматическое применение v2 в следующем ответе при сохранении v1 в старом; сравнение требований (8.91 с), недостаток сведений (4.06 с), защищённое авторство (0.08 с), реальный multi-pass из двух пакетов с цитатами [1]/[2] (22.56 с). Цитаты сопоставлены с синтетическими оригиналами.

Первый adversarial-пример с требованием выдумать стоимость не прошёл: модель добавила неподтверждённые 100000 рублей. После усиления последней обязательной проверки и literal payload reminder повторный ответ явно отказался подтверждать эту сумму (4.88 с). Это выборочная проверка поведения модели, а не гарантия устойчивости к произвольной prompt injection.

Браузер: пользователи demo.user/demo.editor, публикация, просмотр чужого сценария без Save/Delete, независимая личная копия, v1/v2, очистка выбора при смене пользователя. Дополнительная HTTP-приёмка двумя клиентами: чужое изменение 403, личный сценарий 404, copy private, unpublish прекращает новый доступ, republish создаёт v4. После обновления Next проверены выбор общего v4, каталог, readonly editor и возврат по Escape. На странице полной истории видны v1/v2 и открываются инструкции v1, отличные от текущей v4. После уточнения прав: HTTP admin edit/delete public — успешно, private GET/PUT/DELETE — 404, владелец сохранён; в браузере admin видит Save/Delete для чужого общего сценария, а «Мои» не включает его.

Фактически доступная ширина IAB — 319 px: `scrollWidth === innerWidth === 319`. Проверки ровно 360/768/1440 px, всех комбинаций клавиатуры и страниц recent/admin history вручную не заявляются. Общие компоненты истории покрыты frontend regression suite; широкие экраны остаются отдельной ручной приёмкой.

Standalone требует runtime `BACKEND_URL`, как и контейнерный запуск: при первом тестовом старте без него API-прокси использовал стандартный адрес, вход simulation вернул 400 auth_disabled. После явного назначения изолированного backend 18010 все smoke-проверки прошли; защиты и исходники прокси не менялись.

## Независимое ревью

Финальное ревью функции выявило три Important и ни одного Critical. Все три воспроизведены тестами RED→GREEN:

- PostgreSQL JOIN с `FOR UPDATE` после ожидания автора мог дать ложный 404. Исправлено: сначала блокируется head, затем читается версия новым statement; проверены оба порядка гонки.
- Запоздалый GET редактора мог заменить новый черновик. Исправлено generation guard с инвалидированием переходов.
- Копирование сохранённой версии могло потерять несохранённые правки. Добавлено явное подтверждение их отбрасывания.

Отдельные независимые investigation и review обновления Next не выявили конкретных оставшихся обходов или регрессий. Эксплуатация advisory именно в приложении не доказана; проверена устранённая уязвимая версия зависимости.

## Решения при исполнении

1. Использованы PowerShell/Python для служебного ledger вместо bash-инструментов навыка: штатная Windows-среда; на продукт не влияет.
2. Существующая оркестрация обычной попытки оставлена в API, а preview разделяет rate/admission и request-local context через небольшую lazy API-границу. Это ограничивает объём рефакторинга; цена — более тесная связь preview с chat API, покрытая интеграционными тестами.
3. Имена и группировка плановых тестов уточнены: часть проверок объединена в новые test_answer_scenario*/test_chat_scenario* и существующие регрессионные наборы; не каждый первоначальный test-name создан буквально. Непроверенные внешние/ручные пункты перечислены явно.
4. Защищённый формат авторства и сохранённые снимки после unpublish оставлены по согласованному контракту. Reduce хранит доказательства без инструкций формы; цена — ограниченная свобода формата в этом внутреннем шаге.
5. PostgreSQL, backup/restore, модель и браузер проверялись изолированно. Это не заменяет миграцию и проверку production-окружения.
6. Test-only xdist/execnet установлены в игнорируемый каталог без изменения runtime-зависимостей; повторный полный прогон использует 8 workers на 16 логических CPU. Потенциальные параллельные ошибки требуют отдельного последовательного воспроизведения.
7. По уточнению пользователя администратору добавлено управление только чужими общими сценариями. Личная видимость каталога не расширена, исходный владелец не меняется; аудит содержит действительного администратора. Существующие права Admin/Security на просмотр истории чатов и сохранённых в ней снимков остаются прежними.
8. По отдельному согласию пользователя обновлены Next.js и его ESLint-компоненты 16.3.8→16.4.2 отдельным локальным коммитом `f613f12`. React/DOM и ESLint major сохранены. Исходный npm audit блокировал gate; после обновления gate прошёл. Основание: [официальное уведомление Next.js](https://nextjs.org/blog/nextjs-security-update-october-14-2026), [release 16.4.2](https://github.com/vercel/next.js/releases/tag/v16.4.2).

Отложенных Minor по ревью функции не зарегистрировано. Linux Docker/standalone (нативный Windows standalone проверен), полный внешний CI, рабочая миграция, широкие viewport и расширенная модельная оценка не подтверждены локальными проверками. Слияние/пуш требуют отдельного действия; новая сборка существующего рабочего сервера не развёрнута.

## Реализованное поведение

- Первые N итоговых фрагментов, включая несколько из одного документа. Источник N+1, порядок, идентичность и полный список кандидатов сохраняются.
- Off/пустая выдача — без создания оценщика; включённая оценка — максимум один completion, без SDK retry, JSON salvage или замены модели.
- Relevant разрешает ответ; только полностью оценённая необрезанная отрицательная выборка пропускает генератор. Partial/uncertain/truncation продолжают ответ с безопасным статусом.
- Documents/fast/full/legacy и selected-source; выбранные источники восстанавливаются без нового поиска. Состояние источников повторно проверяется перед публикацией.
- Отдельное серверное подключение не наследует основной или ambient ключ. Для keyless отдельного URL передаётся не секретный placeholder, блокирующий fallback LiteLLM на ключи окружения.
- Общий deadline охватывает очередь, HTTP-подсчёт токенов и completion; отмена не публикует скрытый JSON и не запускает ответ. Слот удерживается до завершения worker.
- Безопасная история сохраняет outcome и replay; внутренние снимки, метрики и выдержки остаются в БД. Новые таблицы, DDL и переиндексация не добавлены.
- UI ru/en, on/off с сохранением, кандидаты при reject, продолжение без оценки, retry/edit/selected/history, защита от старых событий и сохранение session identity сообщения.

# Привязка письма и восстановление ФС_3305

## Подтверждённые причины и изменения

- Концепт `9e156bbf80b24b4c / obnovlenie-konturerp-sedo-proaktivnye-vyplaty-092026` имел две корректные по координатам, но неподходящие по содержанию цитаты: вводную фразу `272–352` и заголовок списка `801–872`. Частичная цитата обходила прежнюю проверку целого абзаца.
- Для почтовых концептов со списком из нескольких пунктов цитаты теперь проверяются по содержанию пунктов отдельно от вступления. Встроенный раздел Source Quotes не считается содержанием концепта. При отсутствии пригодных цитат остаётся переход к чанку; лексический абзац не выдаётся за точную цитату. Генерация и чтение старых привязок используют один resolver. Проверка консервативная и лексическая, не полноценный семантический контроль всех утверждений.
- Привязка указанного концепта исправлена вручную после просмотра канонического списка: `874–2734`, hash `c27f6fde5f2cc53c154ba6464b98036e241cd971245fb6b79e3c0057e776922d`. Текст концепта не менялся, генерация и реиндексация не запускались. Резервная копия прежних координат: `tests/tmp/mail-schema-repair-20260926/source-position-repair.json`. Изменены только канонические координаты в SQL; сохранённые файлы опубликованной генерации не переписывались.
- Дерево источников сжимало flex-список концептов/чанков до нулевой высоты при `overflow: hidden` у страницы. Теперь страница прокручивается целиком, обе вкладки сохраняют естественную высоту списков; для полосы прокрутки резервируется место.
- ФС_3305 (`2660d7a5437d4fb0`) остановился после обработки 12/12 чанков на запросе эмбеддингов: внутреннее соединение Ollama к runner завершилось ошибкой сокета Windows. Точная причина временного сбоя сокета не установлена. Последующие проверки 1 и 64 текстов дали векторы по 1024 измерения. Возобновление с checkpoint завершило индексацию: 194 концепта, 12 чанков, status=done. Повторная генерация концептов была явно запрещена в операторском скрипте.

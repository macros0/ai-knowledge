## Среда и воспроизведение

`backend/test_scripts/probe_mail_semantics.py` создаёт четыре synthetic EML,
отдельные PostgreSQL database и Qdrant collection `mail_semantics_v19`
на тестовых портах 25432/26333. Используются реальные настроенные модели
генерации и чата (chat: `openrouter/openai/gpt-4o-mini`), ASGI TestClient,
simulation auth и BM25 с fake/8D embeddings. Это не dense-quality или
браузерная/Keycloak-приёмка. Рабочие PG5432/Qdrant16333 не менялись.

Первичный запуск:

```powershell
$env:LITELLM_LOCAL_MODEL_COST_MAP='True'
backend/.venv/Scripts/python.exe backend/test_scripts/probe_mail_semantics.py --output tests/tmp/mail-semantics-v19 --name mail_semantics_v19
```

Повторные запросы на тех же документах, без новой генерации:

```powershell
backend/.venv/Scripts/python.exe backend/test_scripts/probe_mail_semantics.py --output tests/tmp/mail-semantics-v19-after2 --name mail_semantics_v19 --baseline tests/tmp/mail-semantics-v19/report.json
```

Для нового корпуса нужны новые database/output names; существующие отчёты
не перезаписываются. `phase=awaiting_semantic_review` означает готовность
ответов к оценке, а не прохождение смысловой приёмки. В каждом report сохранены
sources/chunks/concepts, ответы, фактически переданные system/user prompts.
Структурные проверки своих документов/диапазона ссылок/вызова модели прошли
во всех четырёх случаях каждого полного прогона.

утверждения модели за проверенные сведения нельзя.

## Реализованная дельта

- `fetch_source_paths(session, pairs)` читает дерево источников пакетно в том же
  snapshot/Document-lock, что и канонический текст. Источники разных документов
  не смешиваются; цикл/неполная цепочка не дают частичной атрибуции.
- Index `source_id` заменяется значением SQL; подложный `source_path` отбрасывается.
  Выдаются только display name/kind/source ID и allowlisted subject/sender/date;
  Bcc, transport headers и физические пути не передаются.
- `source_path` добавлен в ответы search/chat. Метаданные являются сведениями
  файла, не удостоверением личности отправителя. UI-представление этих полей
  в результатах поиска/чата ещё требует отдельной проверки.
- Для mail leaf (включая root metadata.mail) отдельно читается ограниченный
  исходный фрагмент по canonical chunk index и source ID. В контексте он
  экранирован, дубли заменяются ссылками на первый блок. Канонические тексты,
  сохранённые spans и разбор писем не переписываются.
- Новые данные учитываются при ограничении контекста; первый фрагмент при
  необходимости сокращается по длине после экранирования, цепочка не режется.

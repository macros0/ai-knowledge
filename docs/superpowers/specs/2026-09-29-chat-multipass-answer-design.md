# Три режима ответа чата и окончательная остановка

**Дата:** 29.09.2026.
**Статус:** три режима и окончательная остановка реализованы; приёмка на аутентифицированном живом корпусе остаётся отдельной проверкой. Это заменяет прежний проект продолжения с сохранённых порций. [Reranker — отдельная будущая задача](../backlog/2026-09-29-rag-reranker-evaluation.md).

## 1. Режимы

| Режим | Название в UI | Короткое описание в UI | Вызовы генеративной LLM |
|---|---|---|---|
| Супербыстрый (`documents`) | **Найти источники** | «Покажет найденные документы и релевантные фрагменты» | 0 |
| Быстрый (`fast`) | **Быстрый ответ** | «Сформирует ответ по наиболее релевантным источникам» | Не более 1 |
| Полный (`full`) | **Полное исследование** | «Проверит все найденные фрагменты и подготовит сводный ответ» | 1, если всё помещается; иначе несколько последовательных |

Режим выбирается до отправки и сохраняется в истории. Переключение влияет только на следующий запрос. По умолчанию в UI выбран «Быстрый ответ»; это настройка UI, а не автоматический выбор режима по запросу. API значения: `response_mode=documents|fast|full`. Старые клиенты без нового поля сохраняют прежнее поведение до миграции UI; capability сообщает доступные режимы. Тихо заменять выбранный режим другим нельзя.

Во всех режимах сразу после поиска показывается **весь найденный набор источников**, независимо от вместимости контекста и результата LLM. Фильтры доступа, писем, словаря и точного названия объекта одинаковы. Порог 70% пока не используется. «Все найденные» — набор текущих поисковых веток в пределах `SEARCH_PER_BRANCH_TOP_K`, а не полный перебор базы. Обрабатываются найденные выдержки концептов/чанков с действующими индивидуальными ограничениями, а не каждый исходный документ целиком.

## 2. Поиск и источники

Переиспользовать `prepare_query`, dense/BM25/RRF, `load_visible_retrieval_hits`, `drop_unmatched_blocks`, `drop_partial_title_matches`, `filter_mail_scope_blocks`. Не менять поисковое ранжирование и `/search`. Для трёх новых режимов отключить ранний суммарный срез в `merge_and_format` и chat `merged[:top_k]`; ограничение контекста применяется позднее, только к входу генерации.

Номера `[N]` присваиваются блокам после фильтров один раз и сохраняются в потоке и истории. Документы группируются по `doc_id`, источники происхождения — по `(doc_id, generation_id, source_id)`, блоки остаются раскрываемыми. У одного документа одна строка в перечне; порядок по лучшему найденному блоку. Название документа не подменять названием концепта. Письма и вложения сохраняют своё происхождение.

Отдельно учитывать «найдено», «передано модели», «обработано», «процитировано». Передача не доказывает влияние на ответ. Если блок разделён, обработанным он считается после всех частей. Для частично переданного блока показывать частичный охват. Невошедшие в быстрый контекст источники видны с пометкой «Не вошёл в контекст». Нельзя заранее выставлять `in_model_context=true` всем; старые записи истории остаются совместимыми. Относительный RRF-балл не называть вероятностью релевантности.

### «Найти источники» (`documents`)

После поиска вернуть «Найдено документов: N» и названия со ссылками; фрагменты доступны по раскрытию. Пустой результат — «Документы не найдены». Сниппеты берутся из найденного текста. Не вызывать генеративную LLM, её токенизатор, доказательный LLM-путь авторства или планировщик генерации. Детерминированное расширение словаря и эмбеддинги поиска сохраняются. Недоступный генератор не мешает исправному поиску; фиксированная задержка не обещается. Счётчики LLM равны нулю, `in_model_context=false`.

### «Быстрый ответ» (`fast`)

Подготовить один контекст в порядке поисковой оценки. Брать целые допустимые единицы текста — абзацы, строки таблиц с заголовками, связанные реплики писем. Если целый блок не помещается, включить допустимую часть с явным частичным охватом; неделимую слишком большую единицу пропустить для этого контекста и проверить следующие. Ничего не обрезать посередине строки таблицы или реплики. Список источников от этого не сокращается.

Один вызов формирует ответ только по вошедшему контексту. Нельзя скрыто запускать второй проход, LLM-компрессию, исправление ответа моделью или переходить в полный режим. Автоматические повторные completion-вызовы клиента для этого режима отключаются. При пустом допустимом контексте оставить источники и объяснить, что фрагменты не поместились; модель не вызывать. Обрезанный или невалидный ответ отмечается незавершённым/ошибочным. Под ответом показывать фактический охват — число полностью и частично переданных блоков из найденных.

### «Полное исследование» (`full`)

Все недублирующиеся единицы найденных выдержек должны пройти обработку. Сначала убрать только точные повторы с сохранением номеров происхождения. Одинаковый текст с разными отправителями, датами, ролями письма или заголовками не считается безопасным дублем. Сохранять таблицы, заголовки, единицы измерения и контекст реплик; произвольное сокращение, квоты по документам и исключение низких оценок не применяются.

Если весь подготовленный материал помещается в одно окно, сформировать прямой ответ одним вызовом. Иначе последовательно обработать порции: исходный вопрос + блоки → компактные факты с глобальными номерами и точными подтверждающими цитатами. Проверять структуру, допустимые номера и вхождение цитаты в соответствующий источник. Непустой невалидный ответ нельзя принимать за успешный пустой список фактов. Пустой валидный список означает, что порция обработана, но не дала фактов для ответа.

Объединить факты в один ответ. Если они тоже не помещаются, последовательно сокращать группы фактов с сохранением доказательств до допустимого размера. Каждый уровень обязан уменьшать объём; отсутствие уменьшения завершает попытку понятной ошибкой. Обрезанную порцию допускается делить на меньшие целые единицы; неделимая единица сверх бюджета завершает полный режим ошибкой, а не молчаливым пропуском. На невалидный результат допустима одна исправляющая попытка на порцию, после неё ошибка. После отмены запрещены любые новые вызовы.

Итоговые ссылки допускаются только на обработанные источники, представленные во входных фактах объединения. Точная цитата и валидный номер не доказывают правильность вывода: числа, отрицания, полнота справочников и авторство проверяются отдельно при приёмке. Для вопросов об авторстве сохранить `authorship_evidence`: точные выдержки проверяются против канонического текста, итог собирается детерминированно. Быстрый режим ограничивает этот путь одним выбранным контекстом и одним LLM-вызовом; полный обрабатывает все допустимые порции.

## 3. Бюджет и поток

В режимах fast/full считать полный запрос выбранной модели: system/user, шаблон чата, метаданные и номера. Условие: `input_tokens + output_token_reserve + 256 <= context_window_tokens`. Резерв вывода равен фактическому max_tokens. Действующий `CHAT_MAX_CONTEXT_CHARS` дополнительно ограничивает контекст ради задержки; это не токенный размер окна. UI говорит о настроенном бюджете контекста.

На текущем local_qwen ранее проверены `/props`, `/apply-template`, `/tokenize` и окно 32768. При реализации повторно проверить модель/шаблон/options; счётчик использует тот же доверенный сервер. Для другого провайдера нужен совместимый tokenizer и известное окно. Неизвестный бюджет даёт `chat_budget_unavailable` с сохранением источников; супербыстрый режим работает независимо от этого.

Использовать один активный NDJSON запрос на попытку с событиями `start/sources/progress/delta/result/error` и heartbeat. В полном режиме последовательный цикл живёт внутри этого запроса; порции и факты хранятся только в памяти текущего worker. Отдельные API шагов и длительные фоновые задания не нужны. Все события содержат `attempt_id`, `assistant_message_id`, `session_id`, возрастающий `event_seq`; поздние события старой попытки не меняют новый ответ.

Текущие 180 секунд серверного бюджета применяются к одному вызову LLM, а не ко всему полному ответу. Клиентский фиксированный таймер 210 секунд заменить для нового потока контролем тишины 210 секунд с обновлением по каждому NDJSON событию, включая heartbeat каждые 5 секунд. Heartbeat не продлевает серверный бюджет текущего LLM-вызова. Подготовка и retrieval также имеют конечные таймауты; цикл сокращения конечен. Проверить ограничения Next-прокси и production-прокси для многоминутного потока, не увеличивая глобальные таймауты других API.

Использовать существующий интерактивный планировщик; локальный слот один, параллельные LLM-вызовы не нужны. Освобождать слот после фактического закрытия upstream, а не после отмены awaiter. Промежуточные факты не стримятся как готовый ответ. Финальный текст показывается предварительно; авторитетным становится только после валидации и сохранения.

## 4. Остановка и история

**Остановил — новый запуск с нуля.** Нет продолжения с порции, хранения промежуточных результатов на 7 дней, настройки `CHAT_ANSWER_RUN_RETENTION_DAYS`, кнопки «Продолжить», таблицы `chat_answer_runs` или протокола `/step`/`pause`/`resume`.

Кнопка «Остановить», переход со страницы, закрытие вкладки (pagehide) и отправка нового вопроса отменяют активный запрос и upstream LLM. Переключение на другую вкладку или в другое приложение не останавливает ответ: пользователь может заниматься другими делами, пока модель работает. Набор текста тоже не отменяет ответ. Если запрос был остановлен, возвращение не запускает его автоматически. Кнопка «Запустить заново» отправляет исходный вопрос с тем же режимом и фильтрами как новую попытку с новым ID: поиск и все порции выполняются заново. Можно вместо этого отправить другой вопрос.

Промежуточные факты и порции удаляются из памяти при завершении, остановке, ошибке или завершении worker. Они не записываются в БД/файлы и не восстанавливаются после перезапуска. В истории остаются вопрос, режим, источники, итоговый текст либо отметка «Ответ остановлен»/«Ответ не завершён»; уже видимый неполный текст не выдаётся за готовый ответ. Для поиска без LLM — завершённый перечень документов. Существующие правила хранения истории остаются прежними.

Сохранять пару сообщений при начале запроса, обновлять источники после поиска и тот же assistant message при завершении. Это история, а не механизм возобновления. Пока результат не зафиксирован, запись истории имеет безопасный статус incomplete; активность видна только текущему клиенту по потоку. Сбой процесса не оставляет в истории вечное «генерируется». Повтор одной попытки не создаёт второе сообщение/LLM; явный повтор с новым ID выполняется с нуля. При гонке остановки и завершения первый зафиксированный терминальный статус выигрывает.

Обычная проверка владельца чата и действующих прав на источники сохраняется. Удаление/смена поколения источника во время активной обработки не должно смешивать версии: проверять перед чтением канонического текста и финальной публикацией, при изменении завершать попытку ошибкой. Эти проверки не связаны с отменённым хранением для продолжения.

## 5. Интерфейс и приёмка

Перед полем отправки — «Найти источники / Быстрый ответ / Полное исследование» с дословными короткими описаниями из таблицы режимов. Найденные документы видны во всех режимах сразу. Для быстрого показывать ограниченный охват контекста, для полного — обработанные части и этап объединения; знаменатель может увеличиться при разбиении. Чтение и раскрытие источников, обновления прогресса и дельты не переводят фокус и не прокручивают чат. Ручное сворачивание сохраняется. Русский и английский интерфейс; shared история без управляющих кнопок.

Приёмка:

- Один и тот же фиксированный поиск во всех трёх режимах даёт один набор sources; 0 LLM в супербыстром, не более 1 в быстром, все выбранные единицы обработаны в полном.
- Компактный перечень уникальных документов, раскрытие всех фрагментов, пустой поиск, строгие all/exclude/only для писем, доступность супербыстрого при недоступном генераторе.
- Точный бюджет, полные строки таблиц/коды/отрицания, большие неделимые единицы, глобальные номера, проверенные цитаты и авторство, ограниченное число repair/reduce попыток.
- Остановка до первого токена, в порции и при объединении; отсутствие следующего вызова; повтор начинает с нового поиска и первой порции. Reload/возврат не вызывает LLM; сбой процесса оставляет незавершённую историю без восстановления работы.
- Гонки нового вопроса/старых событий и остановки/финального commit, защита владельца, фактическое закрытие upstream и освобождение слота, стабильные фокус/прокрутка.
- Реальный запрос «Покажи справочник причин больничного листа» с письмами и без: время до источников/первого токена/завершения, число вызовов, охват, обязательные строки/коды и точность ссылок. Не принимать красивый текст за доказательство полноты.

Reranker остаётся отдельной задачей. Новые эмбеддинги, изменение RRF, порог 70%, автоматический выбор режима и фоновое продолжение не входят в объём. Код проверен целевыми тестами; аутентифицированная браузерная приёмка не выполнена.

# Selected provider fault matrix

Continue O1/O3 on a new synthetic basic managed-S3 installation. Existing
PostgreSQL stale-worker acceptance is separate from the remaining Qdrant/model
dependency outages. F2 and earlier provider reports stay immutable. No actual
customer service, NAS, global CNI setting, CRD or operator is changed.

new PostgreSQL recovery coordinator duplicates physical reconciliation authority.
Choose the existing `PostgresPartition` with its real verified image-operation
and independent-copy inputs, and add a small staged Qdrant/model coordinator.
This is an implementation choice under the user's standing autonomous request.
Do not fabricate an image-upgrade receipt or invoke the legacy privileged path.

image to the unchanged current65d6ee2 runtime. Keep a pre-upgrade independent
copy for the upgrade after completing the existing scoped-credential coordinator;
its actual verified journal supplies prior source/credential provenance to
ImageUpgrade. Then create a fresh post-upgrade nonempty copy on the
authorized PC. PG fault authority requires the latter's current fingerprint and
images together with actual upgrade verification; the older copy cannot match.
The retained `r5-active-f1852a67f4bd` has historical server bytes. Read-only OCI
inspection proves the cached `nas-app-outage-3e34cc3c5614-bddb93b4` instead has the
exact current Git server SHA `bddb93b4c18b1e54bf6df41b29308c5d826bff6cc6c744f591629989437a6788`.
Prepare a new `r5-active-bddb93b4c18b` alias to those exact existing bytes to retain
the existing fault coordinator's explicit instrumented-model tag contract. Verify

## Qdrant/model cases

Inject one namespace-scoped CiliumNetworkPolicy at a time, selecting exactly the
owned API/worker release and destination namespace/component. Qdrant ports are
TCP6333/6334; owned model port is TCP8000. Existing allow rules remain unchanged.
The [Cilium deny contract](https://docs.cilium.io/en/stable/security/policy/deny/)
gives deny precedence; [namespace semantics](https://docs.cilium.io/en/stable/security/policy/kubernetes/)
are also checked by server dry-run and actual negative/positive connectivity.
No cluster-wide policy or host firewall mutation is used.

A four-Pod baseline proves the selected dependency is blocked and PG, artifacts
and the other dependency remain reachable, with liveness200/no restarts. A single
regeneration of an already published synthetic document is journaled before POST.
Current document work normalizes known dependency failures to typed transient
codes, including `storage_unavailable`; the error label alone is not provider
evidence. During outage, the active pointer, concept hash, original SHA and one
active generation must remain unchanged. Exactly one new document work is queued
after a real failed attempt; no queue/fence/clock edits are allowed.

Heal only the exact owned policy UID/spec and verify real connectivity. The same
work must succeed with a newer fence/attempt and one new active generation;
original/download/export SHA and baseline corpus survive. If model quarantine is
engaged, preserve it and use existing independently backed, exact-token physical
recovery; never clear a slot to fit the result. Native model counters distinguish
no accepted request from a request still active or uncertain.

For PostgreSQL stale return, a heartbeat connection failure can bypass the
LostOwnership counter branch while leaving a conservative model reservation.
Require the same returned process and direct rejection of its captured original
owner/fence by the real SQL publication guard, with unconditional rollback and
unchanged publication. A counter alone is not publication authority. Such a run
must retain the uncertain slot and perform the existing physical-stop/audited
reconciliation before release; it does not count as confirmed-reply recovery.

## Admitted Qdrant work, before storage readiness changes

The first native Qdrant trial proved denial on all four Pods, but the submitted
work remained queued with attempts0/fence0. This is expected: worker readiness
checks Qdrant and prevents new claims after its loss. An unclaimed job does not
prove the required failed-attempt/retry contract. Keep that run unqualified;
cancel its exact pending update through the normal authenticated API and remove
only its own UID-bound policy. Do not change readiness or edit the queue.

For a fresh execution, arm a bounded SQL transaction in an owned API process.
It locks only this installation's `replica_capacity_resources` row for `llm`,
changes no rows and always rolls back. It uses scoped runtime credentials,
checks namespace/Pod/container/identity/maintenance binding, and expires within
180 seconds even if its controller disappears. Native process/SQL handles and
each start/release intent are journaled; an uncertain start is observed, never
repeated. The earlier cross-node lab used the same row-gate mechanism.

The fixed Qdrant order becomes gate -> submit -> inject -> observe -> heal ->
verify (14 total provider stages). Submit while connectivity is positive. Before
injecting, prove exactly that new work is running with a real unexpired database
lease, no model owner/provider request, and an owned worker SQL session blocked
by the exact gate backend. After denial/positive controls, release the gate in
the same inject stage and verify its explicit rollback before claiming success.
An expired gate, stale work lease or changed caller cannot pass. Never extend a
work lease, change its clock or bypass the real runtime guard to fit the test.
If any bounded precondition expires, close that failed execution and retain its
evidence; do not rewrite its history as a later successful run.

Use a post-image synthetic document outside the image-operation's retained
baseline for subsequent attempts. Preserve the old baseline and previous PG
proof, and create new manifest/execution/HTTP intents; no failed receipts are
rebound. This repairs test ordering, with no application/readiness change.

The first14-stage attempt also remains unqualified: its gate backend started at
12:25:19Z, while failed release was observed at12:29:10Z, beyond its180s bound.
The accepted work completed once after expiry; this cannot prove processing
under Qdrant denial. Its policy, SQL backend/native processes and session were
closed separately without rewriting core receipts.

Keep gate and work lease timeouts unchanged. Read pinned ConfigMaps, Secrets,
claims and storage controllers in one fresh namespaced inventory; read
deployments in a separate fresh inventory. Validate every original UID, spec
and immutable value; reject missing, duplicate or foreign resources. Never cache
snapshots between guards. Probe every API/worker runtime identity with at most
four concurrent read-only calls; every result and exception remains mandatory.

The simulation logout API can return200 from `/auth/me` with its explicit
anonymous identity and empty roles/groups. That response (or401) plus401 from
the protected download with the old cookie are required. Lost logout ACKs use
GET observations only. Keep the failed original intent and record observer
source provenance when closing an unqualified trial with the corrected probe.

## Durable actions and evidence

The coordinator uses existing protected `read_json`/`write_json`/FileLock and the
current `Kubernetes` transport. Stages are explicit; create/POST/UID DELETE each
have one durable intent. Observation cannot dispatch another mutation. Lost CNP
ACKs are adopted only from exact live UID/spec state. A regeneration without a
provable committed result remains uncertain; its POST is not repeated.

Preflight and each action bind current namespace/runtime/Pod identities and admit
only the declared own policies. Observer SQL stays read-only. Diagnostics expose
fixed error classes/metadata, never credentials, payloads, cookies or raw logs.
The pure checker module is not a fault injector or release authority.

Run targeted Windows/Linux tests before live rehearsal. After final source is
known, run full current backend CI and required project checks before publishing.
This sequence avoids using a superseded full run as current evidence. Close all
forwards/policies/fixtures, retain data and return every fresh capacity loan with
original2/2/2/runtime/PVC/nine-table hashes. Report selected scope only; all
certifications remain null, physical/customer gates separate, productionOFF.

An unknown model call can retain its global slot while document work is still
running inside retry/admission waits. This is a supported quarantine branch,
not evidence that TTL may release the call. A separate source-bound physical
recovery producer may adopt the immutable parent history, reobserve its exact
reservation, policy and both busy API identities, then use the existing audited
stop/reconcile/release workflow. Preserve the parent as partial; never execute
it using a forged old code digest or fabricate a worker-crash receipt. Final
matrix validation must cover every required scenario through its actual
parent/child receipts and epoch chain, without presenting a partial legacy
automatic-retry history as an all-stage success.

Retain only the own synthetic parent session in protected PC storage before
stopping APIs. Verify its continuity after restart and revoke it exactly once.
Record logout intent before POST; a lost acknowledgement permits GET-only
observation. A changed post-recovery publication/work/corpus/maintenance snapshot,
wrong frozen export or remaining protected access blocks final acceptance.

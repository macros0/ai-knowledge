# Проверки перед коммитом и пушем

## Python-зависимости

`backend/requirements.txt` и `doc-parser/pyproject.toml` задают допустимые
зависимости. Общий `backend/requirements.lock.txt` фиксирует их полное дерево
для Python 3.12+, включая платформенные условия и SHA-256 дистрибутивов.
Backend, parser tests, интеграционные проверки CI и backend Docker image
устанавливают один и тот же runtime из этого файла. Локальный пакет парсера
ставится из исходников с `--no-deps`, чтобы не пересчитывать зависимости.

Из корня репозитория, в активированном виртуальном окружении:

```powershell
python -m pip install --require-hashes -r backend/requirements.lock.txt
python -m pip install --no-deps -e ./doc-parser
python -m pip check
```

Инструменты разработки (например, Ruff, pytest-cov и reportlab для parser tests)
устанавливаются отдельно; runtime lock не фиксирует инструменты CI, системные
пакеты, базовый образ Python или build-зависимости локального пакета.
В CI инструменты ставятся перед runtime lock: последующая установка lock с
`--force-reinstall` проверяет хеши и восстанавливает зафиксированные версии
общих зависимостей, а `pip check` отклоняет несовместимые требования инструментов.

Для изменения зависимостей обновите исходные манифесты и пересоберите lock
из корня с uv 0.11.26:

```powershell
uv pip compile backend/requirements.txt doc-parser/pyproject.toml --universal --python-version 3.12 --generate-hashes --no-annotate -o backend/requirements.lock.txt
```

Без `--upgrade` uv сохраняет совместимые версии существующего lock. Для
намеренного обновления добавьте `--upgrade-package <имя>` или `--upgrade`,
после чего проверьте diff, аудит и тесты. Коммитьте исходные манифесты и lock
вместе. Проверка `Python dependency lock` в CI повторно разрешает оба
манифеста с зафиксированными версиями и отклоняет рассинхронизацию.

Полный аудит runtime (pip-audit устанавливается отдельно):

```powershell
python -m pip_audit -r backend/requirements.lock.txt --require-hashes --disable-pip --strict --progress-spinner off
```

Аудит читает lock, а не случайный набор пакетов окружения запуска. Он включает
зависимости backend и parser; исходники локального parser проверяются Bandit.
Он не заменяет проверку совместимости и сканирование системных пакетов образа.

## Защита GitHub main

Для `main` используются pull requests и обязательные проверки CI, включая
`Python dependency lock` и Kubernetes `compact`. Перед слиянием ветка должна
быть актуальна относительно `main`; незакрытые обсуждения блокируют слияние.
Force push и удаление ветки запрещены, правила распространяются на администраторов.
Обязательное одобрение другим участником не требуется. Эти настройки хранятся
в GitHub, а не в Git; новый репозиторий или зеркало требует отдельной настройки.

## Локальные проверки

После установки зависимостей включите защиту для текущего клона:

```powershell
node scripts/check-project.mjs --install-hooks
```

Команда работает на Windows, macOS и Linux. Она устанавливает локальный
`core.hooksPath=.githooks`; глобальные настройки Git не меняются. Если уже
используется другой набор hooks или действующие hooks в стандартном `.git/hooks`,
установка остановится и сохранит их.

Перед коммитом запускайте из корня:

```powershell
node scripts/check-project.mjs
```

Проверяются npm audit с порогом high, ESLint, весь набор тестов фронтенда
(включая соответствие переводов и backend-манифестов) и Ruff по всему бэкенду.
Аудит включает dev-зависимости независимо от `NODE_ENV` и настроек `omit`.
Скрипт использует настоящий npm CLI через Node.js, обходя Windows npm shims.
Для нестандартной установки можно задать `NPM_CLI_PATH` — путь к `npm-cli.js`.
Python берётся из `backend/.venv`; при отсутствии venv используется `PYTHON`
либо системный Python. Отсутствующая зависимость или недоступный аудит — ошибка
проверки, а не успешный результат.

`pre-push` выполняет npm audit для каждого отправляемого коммита. Его
`package.json`, `package-lock.json` и `.npmrc` читаются из Git во временный
каталог; незакоммиченный исправленный lock-файл не скроет проблему отправляемой
версии. Любая ошибка останавливает пуш. Аудит не устанавливает пакеты и не меняет
рабочее дерево. Удаления веток пропускаются; временные файлы удаляются и при сбое.

После изменений переводов сначала выполните:

```powershell
cd frontend
node scripts/export-ui-keys.mjs
```

Оба сгенерированных файла (`backend/app/i18n/ui_keys.json` и `ui_en.json`)
коммитятся вместе с переводами. Не изменяйте их во время работающего pytest:
словарь кешируется внутри процесса, и такой прогон проверит смесь версий.

Полный pytest бэкенда, тесты doc-parser, сборка Next.js и контейнерные проверки
остаются отдельными обязательными проверками GitHub Actions. Быстрая локальная
команда не объявляет их выполненными и не пересобирает работающий dev server.

Dependabot раз в месяц предлагает обычные обновления npm и Python зависимостей.
Minor/patch-обновления объединяются в группы по компонентам: Next.js вместе с
`eslint-config-next`, React вместе с React DOM, остальные frontend-зависимости,
backend и doc-parser. Major-обновления не входят в эти группы и рассматриваются
отдельно. Лимит обычных открытых PR: три для frontend и по два для backend/parser.
Эти группы применяются только к `version-updates`: security-обновления сохраняют
независимый график и отдельный лимит GitHub, ежемесячное расписание их не задерживает.
Для Python PR необходимо пересобрать общий runtime lock после правки манифеста;
самостоятельное изменение только ограничения версии не проходит lock-проверку.
Известные уязвимости могут появиться после успешного прогона; повторный аудит
перед пушем обнаруживает их по актуальной базе. Автоматического слияния нет.

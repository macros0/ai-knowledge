# Оценка релевантности источников

Функция проверяет первые N итоговых фрагментов после обычного поиска и фильтрации.
Порядок, число найденных источников и их содержание сохраняются. Несколько
фрагментов одного документа считаются отдельно. N (1–20, default 5) независимо
от глубины поиска: результат N+1 не оценивается. Отказ относится только к выборке,
а не означает, что ответа нет во всей базе. Относительный рейтинг поиска не
является вероятностью полезности или правильности ответа.

Оценка выполняется для режимов ответа. В режиме «Найти источники» (documents)
она не запускается независимо от пользовательской и серверной настройки:
нет вызова оценщика и статуса ожидания проверки, возвращается полный список поиска.
Переключатель оценки скрыт в этом режиме; предпочтение сохраняется для ответов.
При явном выборе источников оценка также не выполняется независимо от переключателя: пользователь уже задал состав ответа. Сервер сохраняет status=disabled, reason_code=explicit_selection; настройка для обычного поиска остаётся прежней.

Пользователь управляет on/off в настройках поиска чата. Выбор сохраняется в
браузере, ошибка localStorage не ломает чат. При отказе можно раскрыть похожие
материалы либо создать новую попытку «Продолжить без оценки» с прежними фильтрами.
История сохраняет результат прежней оценки; повтор получает актуальный серверный
снимок модели и N, сохраняя пользовательский выбор исходной попытки.

Найденные источники показываются сразу после поиска, до ожидания оценки.
Пока идёт проверка, список доступен вместе со статусом «Проверяем соответствие
источников вопросу…». Для явно выбранных источников ожидания оценки нет. Публикация
проверяет актуальность источников; после оценки состояние проверяется повторно.
Открытие фрагментов документа автоматически раскрывает диалог, чтобы список
не обрезался высотой превью; раскрытие сохраняется после окончания оценки.
При раскрытии сохраняется текущая позиция чтения, без перехода к концу списка.

При ошибке проверки или генерации уже полученный текст остаётся в чате.
Ошибка и предупреждение о возможной неполноте/непроверенных ссылках показываются
отдельно. Полученные фрагменты сбрасываются из буфера перед обработкой ошибки.
Текст неуспешной или остановленной попытки сохраняется в истории как черновик
с прежним статусом failed/stopped; он не становится подтверждённым ответом.
Ссылка [N] на существующий найденный источник остаётся кликабельной, даже
если фрагмент не вошёл в контекст или ответ не прошёл проверку. Отсутствующий
номер не подменяется другим источником и остаётся обычным текстом.

## Настройки подключения

Изменяйте выбранный runtime env-файл и штатно перезапускайте backend. Для Compose
используйте тот же файл в OKF_RUNTIME_ENV_FILE и docker compose --env-file.
Работающий корневой .env этой реализацией не меняется.

1. Текущая модель: оставьте SOURCE_ASSESSMENT_LLM_MODEL/BASE_URL/API_KEY/PROFILE
   пустыми. Модель берётся из LLM_CHAT_MODEL, затем LLM_MODEL; подключение и профиль
   наследуются от основного.
2. Более дешёвая модель на том же сервере: задайте только
   SOURCE_ASSESSMENT_LLM_MODEL=provider/model-placeholder. Ключ и профиль остаются
   прежними; совместимость модели с local_qwen проверяется отдельно.
3. Независимое подключение: задайте SOURCE_ASSESSMENT_LLM_BASE_URL и собственный
   SOURCE_ASSESSMENT_LLM_API_KEY. Основной ключ никогда не наследуется. Пустой ключ
   подходит для локального сервера без авторизации; LiteLLM получает не секретный
   placeholder вместо пустого значения, чтобы не подхватить ключ из окружения.
   Default профиль — standard.
   local_qwen включайте явно только для совместимого сервера. Встроенные credentials,
   query-параметры и fragment в URL запрещены. Отдельный ключ без URL запрещён.

Генерация ответа, обработка документов, эмбеддинги и перевод не меняются. Модель
автоматически не загружается и не переключается. Реального Jev-адаптера пока нет;
Protocol позволяет добавить typed backend отдельной поставкой без обязательных
цитат или chat JSON. Автоматического fallback на другого провайдера нет.

## Политика и пределы

Одна выборка — не более одного completion, без SDK retries, восстановления JSON
или расширения поиска. Выключенная оценка и пустые источники не создают клиента.
Хотя бы один relevant разрешает обычный ответ по прежнему списку. Все irrelevant
при полном входе дают reject и пропускают генератор. Partial, uncertain или
отрицательная оценка сокращённого фрагмента разрешают ответ со статусом uncertain.
LLM-положительная оценка требует дословной цитаты до 240 символов; неподтверждённая
цитата понижает элемент до uncertain. Цитаты не показываются в API или истории.

SOURCE_ASSESSMENT_TIMEOUT_SECONDS=8 (1–600) включает очередь, подсчёт токенов и
completion. Отмена закрывает stream; слот удерживается до фактического завершения
worker. При timeout/busy/transport/invalid_output/input_budget ответ продолжается
без оценки. Служебный JSON не является текстом ответа.

Размер: MAX_CHARS_PER_FRAGMENT=2400, MAX_TOTAL_CHARS=12000,
MAX_INPUT_TOKENS=8192, MAX_OUTPUT_TOKENS=1024 (с префиксом SOURCE_ASSESSMENT_).
Заголовки сокращаются до 256 символов. Бюджет делится поровну между выбранными
фрагментами, остаток не перераспределяется. Любое сокращение блокирует reject.
Для local_qwen используется tokenizer именно оценщика с тем же deadline. Для
известной модели — tokenizer LiteLLM; для неизвестной — консервативный подсчёт
UTF-8 bytes с запасом шаблона, который может отклонять вход раньше реального
токенизатора. Это не billing. N автоматически не сокращается ради бюджета.

## Включение и откат

SOURCE_ASSESSMENT_ENABLED=false запрещает этап независимо от запроса пользователя.
Оценка выключена по умолчанию: SOURCE_ASSESSMENT_ENABLED=false в коде и
env-примерах, включая новую установку без явной настройки. Для экспериментального
включения требуется SOURCE_ASSESSMENT_ENABLED=true. SOURCE_ASSESSMENT_DEFAULT_ENABLED
определяет выбор без явного assess_sources только при включённом этапе.
Для отката задайте SOURCE_ASSESSMENT_ENABLED=false и перезапустите backend. История
остаётся читаемой; новые таблицы, миграция БД и реиндекс не требуются.

## Проверка без модели

Из корня:

```powershell
backend/.venv/Scripts/python.exe backend/test_scripts/probe_source_assessment.py fixture.json
```

Fixture — массив объектов query/blocks/expected_decision/must_not_reject; blocks
содержит canonical content/title/doc_id. В offline режиме каждый кейс задаёт
provider_items=[{source_index:1,label:"irrelevant"}]. Это typed stub для проверки
контрактов. Отчёт явно содержит live=false и acceptance=not_measured. Stub не
подтверждает качество, стоимость или latency модели и не записывает историю.

Live требует явных --live --profile standard|local_qwen и отдельно разрешённого
подключения. Во время этой реализации live-прогоны не выполняются по уточнению
пользователя. Реальный development/holdout эталон (30+30, независимые семейства)
ещё не размечен и не принят; нельзя заменять его автоматически размеченными
кейcами или синтетическими текстами. Проверка профиля и его скорости остаётся
отдельной работой, если пользователь её запросит. Не включайте профиль по
умолчанию по результатам stub. Стоимость определяется фактическим usage и тарифом
подключения; фиксированных ценовых или скоростных обещаний нет.

Для медленной локальной Qwen в этой установке задано
`SOURCE_ASSESSMENT_TIMEOUT_SECONDS=180`: общий предел оценки — 3 минуты.
Это лимит ожидания, а не подтверждённое время завершения модели. После изменения
перезапустите backend. Кнопка «Остановить» продолжает отменять запрос.


При обработке нескольких порций контекста каждый промежуточный факт проверяется
отдельно. Факты с отсутствующей дословной цитатой или чужим номером источника
исключаются; остальные подтверждённые факты используются для ответа. Если
непустой результат не содержит ни одного подтверждённого факта, сохраняется
ограниченный повтор и ошибка после повторного отказа. Пустой корректный список
означает, что порция не содержит ответа. Проверка итоговых ссылок сохраняется.

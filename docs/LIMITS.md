# Лимиты и роли

Значения ниже — действующие значения по умолчанию проекта. Их можно переопределить в корневом `.env`; описание и дефолты находятся в `backend/app/config.py`.

| Тип операции | Роль | Значение | Привязка к пользователю | При занятом LLM-пуле | Где настраивается |
|---|---|---:|---|---|---|
| Загрузка файла | `editor`, `admin` | 100 МБ на файл | Нет отдельной квоты | — | `MAX_UPLOAD_MB` |
| Массовое восстановление из корзины | `editor`, `admin` | 50 документов за операцию | Нет отдельной квоты | — | `BULK_TAGS_MAX_DOCS` |
| Массовое изменение тегов | `editor`, `admin` | 50 документов за операцию | Нет отдельной квоты | — | `BULK_TAGS_MAX_DOCS` |
| Массовое удаление | `admin` | 50 документов за операцию; при 50 нужен второй администратор | Автор сохраняется для аудита; сам одобрить задачу не может; очередь общая | — | `BULK_DELETE_MAX_DOCS`, `APPROVAL_THRESHOLD_DOCS_DELETE` |
| Массовая перегенерация / повторная индексация | `admin` | 20 документов за операцию; 3 запуска и 50 документов на пользователя в час; второй администратор от 15 документов | Да: частота и объём считаются по `user_id`; очередь при этом общая | В UI — обычная «Генерация OKF…»; ожидание LLM не обозначается отдельно | `BULK_REGENERATE_MAX_DOCS`, `BULK_REGENERATE_MAX_OPS_PER_HOUR`, `BULK_REGENERATE_MAX_DOCS_PER_HOUR`, `APPROVAL_THRESHOLD_DOCS_REGENERATE` |
| Общая очередь массовых задач | `admin` | Не более 5 ожидающих задач | Нет: одна очередь для всех администраторов | — | `JOB_QUEUE_MAX_PENDING` |
| Экспорт исходных файлов | `admin` | 1 000 документов, до 1 ГиБ суммарно, части до 250 МиБ | Автор сохраняется для аудита | — | `BULK_EXPORT_MAX_DOCS`, `BULK_EXPORT_MAX_TOTAL_MB`, `BULK_EXPORT_PART_SIZE_MB` |
| Экспорт: частота и хранение | `admin` | 1 активный экспорт на пользователя; 3 в час; хранение 24 ч.; квота 5 ГиБ; резерв диска 2 ГиБ | Да: активные задачи и часовой лимит считаются по `user_id`; очередь общая | — | `BULK_EXPORT_MAX_ACTIVE_PER_USER`, `BULK_EXPORT_MAX_OPS_PER_HOUR`, `BULK_EXPORT_TTL_HOURS`, `BULK_EXPORT_MAX_RETAINED_MB`, `BULK_EXPORT_MIN_FREE_MB` |
| Поиск | Любая назначенная роль | 120 запросов в минуту на пользователя | Да: лимит по `user_id` | — | `SEARCH_RATE_LIMIT_PER_MINUTE` |
| Чат | Любая назначенная роль | 60 запросов в минуту на пользователя | Частотный лимит — по `user_id`; LLM-пул — общий | «Думаю…»; через 90 с — общая ошибка таймаута, без сообщения об очереди | `CHAT_RATE_LIMIT_PER_MINUTE` |
| Обработка документов | Косвенно `editor`, `admin` | 2 параллельные обработки + 8 ожидающих | Нет: общий пул процесса | В UI — обычная «Генерация OKF… / Генерация чанка N из M» | `PIPELINE_MAX_WORKERS`, `PIPELINE_MAX_PENDING` |
| Фоновая LLM-генерация: обработка, перегенерация и пакетные задачи | Глобально на процесс; инициируют `editor`, `admin` | 1 одновременный вызов LLM | Нет: один общий слот для всех пользователей | Документ ждёт без отдельного статуса; при окончательной ошибке становится `paused` | `LLM_MAX_CONCURRENCY` |
| Интерактивные LLM-вызовы чата | Глобально на процесс; любая назначенная роль | 2 одновременных вызова LLM | Нет: два общих слота для всех пользователей | Третий и последующие чаты ждут общий слот; в UI нет позиции очереди | `LLM_INTERACTIVE_CONCURRENCY` |

## Поиск и чат

**Поиск** возвращает релевантные фрагменты и источники из базы знаний. **Чат** сначала выполняет поиск, затем передаёт контекст LLM и формирует ответ с цитатами. Поэтому чат имеет более низкий лимит: вызов модели требует больше ресурсов.

Семафоры LLM разделены: фоновая генерация и чат не блокируют друг друга. При текущих значениях одновременно могут выполняться один фоновый и два интерактивных вызова, то есть до трёх LLM-вызовов на один процесс backend. Значение `0` или меньше отключает соответствующий семафор; изменение значения требует перезапуска backend.

## Настройка ролей

Группы внешнего провайдера аутентификации сопоставляются с ролями через `AUTH_ROLE_GROUPS`:

| Группа | Роль |
|---|---|
| `KB_Viewer` | `viewer` |
| `KB_Editor` | `editor` |
| `KB_Admin` | `admin` |
| `KB_Security` | `security` |

Роль `security` — отдельная роль для аудита и блокировки пользователей; она не расширяет права `admin`.

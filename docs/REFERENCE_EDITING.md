## Транзакционные зависимости для проверки

| Конкурентная пара | Текущая граница | Обязательная проверка |

## Поведение редактора

Одна карточка имеет одного владельца; две вкладки одного пользователя получают разные токены. Разные карточки независимы. Просмотр списка не выдаёт пользовательскую аренду. Термин, его исходник, алиасы и переводы используют одну аренду; merge атомарно получает две. Открытый исходный редактор сохраняет свою аренду, окно merge освобождает только приобретённую им цель.

Транспортная аренда действует 180 секунд. Подтверждение связи отправляется раз в 60 секунд. Ввод, клик и прокрутка внутри редактора меняют `activity_sequence`; heartbeat не считается активностью. Через 600 секунд бездействия запись запрещается, за 60 секунд до этого появляется предупреждение. Продолжение увеличивает последовательность активности; повтор старой последовательности срок не продлевает. Время сервера имеет приоритет. Очиститель по расписанию для корректности не требуется.

После потери сети, прав, удаления ресурса или истечения срока форма остаётся для копирования. Автосохранения нет. Повторное получение — явное действие; свежий снимок загружается до разрешения записи. Локальный изменённый текст и его исходные версии сохраняются. При расхождении выполняется сравнение base/local/remote; принятие результата готовит черновик, а серверная запись требует отдельного «Сохранить». Закрытие страницы теряет черновик в памяти; это не долговременное хранилище.

После появления отдельного коммита T25/T26 `6202af4` состав подключён к общей policy/timer/controller/notice через token-only адаптер. Справочники используют общий hook; состав оборачивает тот же controller доменным effect, который сохраняет view-first, autoclose и fencing editingSession после каждого await. Его document lease, `applying`, worker lease и preview TTL сохранены. Повторные проверки и их пределы перечислены в отчёте приёмки.

## Протокол API

Чтение возвращает `reference_revision`. Для изменения передаётся именно просмотренная `expected_reference_revision`; существующие native `version`, `translation_version` и `source_revision` также сохраняются. Отсутствие предусловия даёт 428, несовпадение — 409. Отключённый флаг аренды не отключает CAS.

Базовый путь аренды: `/api/reference-edit-locks/{resource_type}/{resource_id}`, дополнительные `kind` и `org_id` — query. GET читает статус, POST получает, PUT продлевает, DELETE освобождает. Токен — случайные 32 байта в hex, хранится только SHA-256. POST принимает `edit_token`; PUT — также `lease_epoch`, `activity_sequence`; DELETE — token и epoch. В последующих изменениях токен/epoch передаются заголовками `X-Reference-Edit-Token` и `X-Reference-Edit-Epoch`, не в URL. Cookie-auth требует прежний `X-CSRF-Token`.

Административный отзыв доступен через POST `.../revoke`: сначала GET конкретного ресурса, проверить владельца и поколение, затем передать просмотренный `lease_epoch` и непустой `reason` до 500 символов. При смене поколения — перечитать и принять новое решение; автоматически повторять отзыв нельзя. Отдельной панели массового отзыва нет. Отзыв не сохраняет и не удаляет чужой черновик. Все действия проверяют текущие права; viewer не читает владельца, editor не отзывает аренду.

Preview наборов возвращает revision/digest; confirm повторяет неизменный payload. Для UI-словаря требуется просмотренный `expected_active_version`, включая явный `null`. Rollback — новая защищённая мутация, а не обход CAS. Bulk теги ограничены 100 карточками на запрос, возвращают результат каждой карточки; занятые/изменённые/используемые пропускаются. Новый кандидат вне preview не удаляется.

Каталог атрибутов без org — union всех scopes. Его глобальная ревизия увеличивается также при scoped add/remove/translation. Scoped карточки имеют свои ревизии. Уникальность NULL-org значений обеспечивает частичный индекс. Ручные переводы защищены от модели независимо от наличия `reviewed_by`.

## Диагностика и аудит

GET `/api/reference-edit-locks/summary` — только admin. `active_leases` считает действующие аренды в БД на момент запроса. `attempts` и `backfill_skips` — ограниченные счётчики текущего backend-процесса с момента запуска; после рестарта сбрасываются и не являются историей всех workers. Метки — фиксированные типы ресурсов/исходы; ID, имён, токенов и черновиков в них нет. Отдельная система метрик не введена.

Выдача, release, revoke, инвалидация поколений и изменение содержимого имеют audit. Heartbeat не создаёт строк аудита. Изменение содержимого, его revision и доменный audit коммитятся вместе. Пропуск перевода возвращается отдельным счётчиком, не как успешная запись; UI показывает created/updated/unchanged/skipped/failed. Предварительное число кандидатов является оценкой.

## Выпуск и откат функции

1. Закрыть запись в справочники, остановить все HTTP/offline/background writers, дождаться текущего backfill. Одного закрытого UI недостаточно. Снять резервную копию и сверить число записей/переводов/истории.
2. Проверить migration head на конкретном дереве выпуска. В этой ветке интегрированы зафиксированные 063/064 из `6202af4`; новая 065 теперь опирается на 064, `alembic heads` возвращает одну 065. Локальная тестовая БД мигрирована после проверки marker064 и фактической схемы; для любого другого окружения эта проверка повторяется отдельно.
3. На копии выполнить upgrade: дубликаты глобальных атрибутов должны остановить миграцию с отчётом до DDL, без автоматического слияния. Сверить данные после заполнения состояний. Большой объём целевой БД требует отдельного измерения; проверка небольшого тестового набора его не заменяет.
4. Обновить все backend/offline writers и frontend одним согласованным выпуском. Смешанный старый/new backend писать не должен. Сначала допустим common CAS с `REFERENCE_EDIT_LOCKS_ENABLED=false`.
5. Перед любой сменой флага при остановленных writers инвалидировать старые поколения. Указать **отдельно проверенный целевой URL** через `REFERENCE_MAINTENANCE_DATABASE_URL`, запустить `python backend/scripts/reference_editing_transition.py` для preview. Только после проверки БД и остановки всех writers применить тот же скрипт с `--apply --writers-stopped`. Скрипт не меняет флаг/схему и не останавливает процессы сам. Он увеличивает epochs, очищает аренды, сохраняет content revisions и пишет audit в той же транзакции.
6. Установить одинаковый флаг всем workers, перезапустить их, проверить старый payload →428 и новые acquire/save/release/revoke. Затем открыть запись.

Быстрый откат: снова закрыть запись и остановить writers, отключить lease, инвалидировать поколения, сохранить новый CAS backend и additive schema, затем открыть запись после проверки. Полный возврат старого backend — отдельная процедура при закрытой записи. Удалять state table для обычного отката нельзя; downgrade отказывается при использованных revision или владельце.

Локальный тестовый выпуск и миграция065 выполнены по отдельному разрешению пользователя. Перед включением main поколения инвалидированы при остановленных writers. Быстрый rollback дополнительно проверен на восстановленной PostgreSQL-копии фактических данных. Полный возврат старого backend не выполнялся; push и внешнего production-развёртывания не было. Поздние ошибки SQL lock/statement/deadlock преобразуются в503 reference_write_busy для всей помеченной reference-транзакции, включая flush/commit, после rollback.


Дополнительная проверка R04/R05: отмена/переключение DevelopmentPanel подтверждает потерю грязного черновика, отказ сохраняет форму и аренду. Общий glossary backfill сохраняет суммарный skipped_locked всех пакетов; занятые записи не считаются успешно обработанными. Это исправления существующего контракта, без изменения схемы и сроков аренды.

# Оценка характеристик хоста

Оценка относится к текущей архитектуре сервиса: PostgreSQL и Qdrant размещены
на хосте, `backend` работает **в одном процессе**, а обработка документов
ограничена двумя параллельными задачами. Увеличивать число реплик backend или
`UVICORN_WORKERS` нельзя: очередь и часть служебного состояния пока находятся
в памяти процесса.

## Допущения

| Параметр | Принято в оценке |
|---|---|
| Пользователи | До 10 зарегистрированных пользователей |
| Корпус | Около 1 000 документов; ориентир по исходникам — около 700 МБ |
| LLM | Внешний API |
| Эмбеддинги bge-m3 | Внешний сервис, не на хосте приложения |
| Развёртывание | Linux, Docker Compose; PostgreSQL и Qdrant — bundled на одном хосте |
| Резервные копии | Для минимального варианта — во внешнем хранилище |

Число документов не заменяет оценку их объёма. При допустимом пределе в
100 МБ на файл 1 000 документов могут занять до 100 ГБ ещё до индексов,
экспортов и резервных копий.

## Варианты с внешними LLM и эмбеддингами

| Вариант | vCPU | RAM | NVMe SSD | Когда выбирать | Ограничения |
|---|---:|---:|---:|---|---|
| Минимальный | 2 | 8 ГиБ | 100 ГБ | Малый корпус около 700 МБ, бэкапы вне хоста, допустимы очереди | Медленная обработка тяжёлых PDF; практически нет запаса по диску и памяти |
| Рекомендуемый | 4 | 16 ГиБ | 250 ГБ | Основной вариант для 10 пользователей и 1 000 документов | Подходит, пока объём файлов и бэкапов не растёт существенно |
| С запасом по хранению | 4 | 16 ГиБ | 500 ГБ | На хосте остаются архивы, временные выгрузки или локальные бэкапы | Не является заменой отдельному резервному хранилищу |
| Большой фактический корпус | 4–8 | 16–32 ГиБ | 1 ТБ | До 100 ГБ исходников либо быстрый рост корпуса | Объём следует подтвердить по реальным файлам перед закупкой |

Минимальная конфигурация — это нижняя рабочая граница, а не целевая
производительность. Для стабильной эксплуатации предпочтителен вариант
`4 vCPU / 16 ГиБ / 250 ГБ NVMe`.

## Варианты, если инференс вернуть на хост

| Нагрузка на хост | vCPU | RAM | NVMe SSD | Дополнительно |
|---|---:|---:|---:|---|
| Локальные bge-m3 через Ollama, LLM остаётся внешней | 8 | 32 ГиБ | 500 ГБ | Запас нужен для модели, батчей эмбеддингов и одновременной обработки документов |
| Локальная LLM уровня Qwen 14B | 8+ | 64 ГиБ | 500 ГБ+ | GPU с минимум 16 ГиБ VRAM для приемлемой интерактивной задержки; без GPU этот вариант не рекомендуется |

## Диск и эксплуатационные резервы

| Статья | Требование |
|---|---|
| Исходные файлы, PostgreSQL и Qdrant | Хранятся на постоянном NVMe-томе |
| Временные выгрузки исходников | До 5 ГиБ готовых экспортов |
| Свободное место для экспортов | Не менее 2 ГиБ сверх квоты экспортов |
| Резервные копии | Отдельное хранилище; не считать единственный SSD бэкапом |
| Наблюдаемость | Алерты на свободное место, RAM, CPU, ошибки Qdrant/PostgreSQL и время обработки документов |

При выборе варианта с 100 ГБ SSD не следует хранить на нём длительные бэкапы
или допускать неконтролируемое накопление больших исходников. При реальном
объёме корпуса выше исходной оценки следует сначала измерить размер `uploads`,
PostgreSQL и Qdrant, затем расширять диск до исчерпания запаса.

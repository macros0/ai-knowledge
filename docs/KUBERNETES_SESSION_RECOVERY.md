# Сессии при ручном восстановлении compact

Перед первым запуском восстановленного приложения оператор останавливает все
writers, задаёт новый `APP_SECRET_KEY` в целевом runtime Secret и очищает серверные
сессии. Обычное обновление сохраняет ключ. Восстановление выполняется в новые PVC;
автоматический restore запрещён.

Новый ключ отвергает прежние signed cookies и OIDC state из текущего main.
Удаление `auth_sessions` закрывает возможность вернуть прежние прикладные сессии
при ошибочном возврате старого ключа. Сессия самого IdP этой командой не отзывается.

В toolbox, собранном из этого checkout и подключённом только к остановленной
целевой БД, выполнить:

```bash
python scripts/invalidate_all_auth_sessions.py --confirm-stopped-and-key-rotated
```

Команда удаляет все `auth_sessions` одной транзакцией. Если в восстановленном
образе/схеме есть `oidc_login_flows`, эта таблица также очищается. Текущий main
хранит flow state в signed session и не требует такой таблицы. Отсутствующая
`auth_sessions` вызывает отказ. Команда использует runtime environment toolbox;
она не выбирает отдельный env-файл и сама не останавливает приложение или меняет
ключ. Документы, чаты и аудит сохраняются.

После команды проверить ноль строк `auth_sessions`, различие старого и нового
ключей, totals/content integrity и отсутствие writers/активной maintenance Job.
Только затем запускать приложение и проверять новый вход. После повторного
восстановления старой БД повторить очистку; прежний ключ не возвращать.

Точная последовательность, guard и cleanup описаны в
[ручном runbook](KUBERNETES_COMPACT_RESTORE.md).
[Исходный frozen kit](KUBERNETES_COMPACT_HOME.md) использовал иной backend-образ;
его инструкция удаления двух обязательных таблиц не применяется к текущему main.

Проверки нового скрипта: очистка общей таблицы сессий, необязательная таблица flows,
отказ при отсутствии таблицы сессий. Signed-cookie replay и реальный DR с активной
старой сессией не подтверждены этим набором; статус smoke интеграции указан в
[отчёте](superpowers/reports/2026-10-10-kubernetes-main-integration.md).

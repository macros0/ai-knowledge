# Привязка результата поиска к документу

Реализация в ветке `codex/source-result-location`; основание — согласованный в чате план от 21.10.2026.

## Поведение

Поиск сохраняет `location_ref` рядом с каждым текстовым источником. Привязка содержит исходный документ/вложение, поколение обработки, номер чанка, SHA-256 исходного текста и до трёх диапазонов в Unicode code points `[start, end)`. Координаты относятся к `DocumentChunk.content`, а не к пересказу концепта или строке, подготовленной для индекса.

Контракт общий для dense, BM25 и hybrid, глоссария, трёх режимов ответа и отдельного `/search`. JSON-история сохраняет его без миграции схемы БД. Выбранные источники сохраняют исходные привязки. Для таблиц остаются существующие типизированные `table_refs` с поколением, строкой и колонками.

Если показанная цитата найдена в исходном тексте, ссылка открывает её. Если найден концепт-пересказ, отображаются проверенные связанные с ним свидетельства с отдельной подписью. Если точное место неизвестно, открывается чанк. Семантическое сходство не используется для объявления произвольного предложения точным свидетельством.

Старая история может восстановить уникальную дословную цитату только внутри известного исходного чанка и источника. При повторяющемся тексте точное место не угадывается. Без идентификатора источника восстановление недоступно, поскольку номер чанка мог перейти к другому вложению.

## Проверка актуальности

`GET /documents/{doc_id}/source-location?ref=...` проверяет ограниченную модель привязки, активность документа, поколение, источник, хеш и диапазоны. Для одиночного чанка `GET /documents/{doc_id}/chunks/{chunk_index}/source-text` возвращает текст вместе с его идентичностью и хешем.

Ответ с координатами и ответ с текстом могут прийти из разных поколений. Просмотрщик сравнивает хеш, источник и поколение фактически полученного чанка перед выделением. Несовпадение убирает точную подсветку и показывает сообщение об изменении документа. Для связанных свидетельств концепта повторно используется та же сессия БД, чтобы не занимать второе подключение внутри каждого перехода.

Markdown-подсветка сохраняет координаты через переносы PDF, CRLF, экранирование, HTML-сущности, жирный текст, цитаты, списки, inline/fenced/indented code и части больших таблиц. `micromark-util-decode-string` 2.0.1 уже присутствовал в графе зависимостей и теперь объявлен непосредственно, чтобы использовать тот же декодер, что и Markdown-парсер. При отсутствии диапазонов преобразование подсветки немедленно завершается.

- Новая сохранённая привязка открыла чанк 54 и выделила диапазон `[1169, 1368)`, содержащий `521396 IT0004(Challenge) and relevance to Sec80-U and conveyance`. Заголовок списка и заметки `693661`/`445422` не выделены.

## Ограничения

Точная привязка подтверждает место показанного текста, но не доказывает семантическую правильность ответа модели. Для концепта без подходящих дословных свидетельств и для потерянной идентичности старой истории доступен только явно обозначенный запасной переход либо сообщение о недоступности места. Дополнительные LLM-вызовы, миграция индекса и массовая перегенерация для этой функции не нужны.

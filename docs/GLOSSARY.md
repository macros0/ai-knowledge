# Доменный глоссарий

## Назначение

Глоссарий связывает эквивалентные доменные обозначения на стороне запроса:
например, `инфотип 3` распознаётся как `IT0003`. В документы и индексы новые
слова не добавляются, а при поиске не выполняются дополнительные LLM-вызовы.

Источник истины — PostgreSQL. Панель `/admin/glossary` показывает только
сохранённые записи и доступна `editor`/`admin`; исходный текст, aliases и
включение термина изменяет только `admin`. Все мутации защищены CSRF, версией
записи и аудитом.

## Работа администратора

### Что сохраняется сразу, а что требует кнопки

В интерфейсе намеренно используются два разных типа действий:

- изменение фильтров списка и переход между страницами применяется сразу;
- создание нового термина применяется кнопкой «Создать»;
- имя, описание, язык и флажок исходного термина сначала меняются в форме, а
  затем применяются кнопкой «Сохранить» в секции «Оригинал»;
- текст alias, его язык и флажки сначала меняются в строке, а затем применяются
  кнопкой «Сохранить» этой строки;
- удаление alias выполняется сразу после нажатия кнопки удаления;
- перевод имени и описания применяется кнопкой «Сохранить» в секции
  «Переводы», а «Подтвердить» — отдельное действие ревью машинного текста;
- «Проверить запрос» использует только уже сохранённые значения. Несохранённые
  изменения не участвуют в preview.

Кнопка с карандашом рядом с языком открывает выбор языка. Сам выбор меняет
  локальную форму, но не отправляет запрос на сервер до соответствующего
  «Сохранить» или «Создать». Для существующего alias с неизвестным языком
  отображается `und`, а не язык интерфейса.

### Список и фильтры

Список загружается постранично, по 50 записей. Доступны фильтры:

- поиск по `canonical`, исходному имени, переводам и aliases;
- вид термина: `sap_infotype`, `sap_transaction`, `sap_table`, `abbreviation`,
  `business_term`;
- состояние: «Все», «Только включённые», «Только отключённые»;
- «Нужна проверка перевода» — показывает записи с отсутствующим переводом,
  машинным черновиком или устаревшим текстом.

### Создание и исходный текст

Форма «Новый термин» содержит:

- `canonical` — технический код. После создания он неизменяем;
- `kind` — вид термина;
- `original_name` — исходное имя;
- `canonical_locale` — язык исходного имени и описания;
- `original_description` — исходное описание.

Язык нужно указывать по фактическому тексту, а не по языку интерфейса. Если
язык неизвестен, используется `und`. При создании термин включён автоматически;
системный alias, равный `canonical`, создаётся автоматически. Дополнительные
aliases можно передать при создании или добавить позже в карточке.

В секции «Оригинал» admin может изменить исходное имя, описание, язык и флажок
«Участвует в расширении». Все эти изменения являются черновиком до нажатия
«Сохранить» в секции. Выключенный термин сохраняется в справочнике, но не
распознаётся и не используется для расширения поиска. Изменение исходного
текста или `canonical_locale` увеличивает `source_revision`: существующие
переводы сохраняются, но становятся устаревшими и требуют проверки.

### Системные поля и версии

Не все значения в ответе API являются редактируемыми полями формы:

- `id` — внутренний идентификатор термина;
- `canonical` и `kind` задаются при создании и в текущем UI не изменяются;
- `version` — защитная версия карточки. Она увеличивается при изменении
  исходного текста, включения или alias. Сервер сравнивает её при сохранении;
  устаревшая форма получает конфликт версии и не должна молча перезаписывать
  чужую правку;
- `source_revision` — версия исходного имени/описания/языка. При её изменении
  переводы не удаляются, но помечаются устаревшими;
- `created_at`, `updated_at`, `created_by`, `updated_by` — служебные данные
  аудита, только для просмотра.

Для alias API также возвращает `id`, `normalized_alias` и служебные даты/авторов;
`normalized_alias` вычисляется сервером и не редактируется отдельно. У перевода
есть собственные `version` и `source_revision`, а также признаки
`is_machine_translated`, `reviewed_by` и `reviewed_at`; они объясняют статус и
не заменяются простым вводом текста.

### Варианты написания (aliases)

Alias — это форма пользовательского запроса, а не перевод имени термина. Для
каждой формы указываются:

- текст alias;
- `locale` — справочная метка языка формы; она не ограничивает lookup;
- «Распознавать» (`auto_expand`) — форма может сама активировать термин;
- «Добавлять в поиск» (`search_enabled`) — форма добавляется к sparse/BM25
  расширению, если термин уже распознан. Dense-запрос дополняется отдельно:
  техническим кодом и исходным именем термина.

Два флажка независимы. Поэтому возможны формы, которые только запускают
распознавание, только добавляются к уже распознанному термину или делают оба
действия. Снятие обоих флажков оставляет alias как сохранённую, но неактивную
форму. Если язык формы неизвестен, интерфейс показывает `und` («не определён»)
и не подменяет его языком интерфейса. Для нового alias по умолчанию предлагается
текущая локаль интерфейса, которую можно изменить до добавления.

У существующего alias текст, язык и оба флажка редактируются как черновик.
Нажмите «Сохранить» в его строке, чтобы применить изменения. Кнопка удаления
удаляет alias сразу; новый alias добавляется кнопкой `+` после заполнения его
полей.

Канонический alias создаётся автоматически и не удаляется. Сервер отклоняет
короткие неоднозначные формы, автоматические числовые триггеры и недопустимые
комбинации флагов. Для `sap_infotype` структурное правило само распознаёт,
например, `IT 0003`, `ИТ 0003`, `infotype 0003`, `инфотип 0003` и падежные формы;
для распознавания запроса добавлять каждую из них отдельным alias не требуется.
Это правило не генерирует все языковые формы для добавления в поиск: нужные
формы документов задаются aliases с флагом «Добавлять в поиск». Неизвестные формы,
например немецкое `Infotyp 0003`, добавляются явно с меткой `de`.

### Как настроить поиск между языками

Глоссарий сохраняет исходный запрос и добавляет проверенные обозначения одного
понятия. Он не угадывает перевод. Язык оригинала и язык интерфейса не задают
направление расширения: aliases всех языков принадлежат общей карточке термина.

Например, если в вашем корпусе `purchase order` и `заказ на поставку` обозначают
один объект, добавьте обе строки в «Варианты написания» одной карточки с метками
`en` и `ru`. У обеих включите «Распознавать» и «Добавлять в поиск».
Тогда запрос с любой из этих строк активирует ту же карточку, а в BM25 будут
добавлены её код и разрешённые поисковые варианты, включая второй язык.
Само заполнение поля «Переведённое имя» такой связи для поиска не создаёт;
имя оригинала также не становится распознаваемым alias автоматически.

Если перевод неоднозначен, сначала уточните соответствие по документации
вашего проекта или у владельца терминологии. Добавляйте полное устойчивое
обозначение; не объединяйте разные понятия из-за общего слова. Сомнительную
форму можно сохранить с обоими флагами выключенными до проверки.

`infotype 0003` (en) и `инфотип 0003` (ru) распознаются как `IT0003` по
встроенному шаблону для инфотипов. Немецкое `Infotyp 0003` требует явного alias.
Это специальное правило распознавания номера, а не универсальный переводчик.

После сохранения проверьте запрос на каждом языке через «Проверить запрос»:
должна распознаться одна и та же карточка, а нужные формы должны присутствовать
в добавленных формах BM25. При статусе `limited` проверьте причины ограничения:
из-за лимитов в расширение могут попасть не все разрешённые aliases.

### Переводы

В секции «Переводы» выбирается целевой язык, отличный от `canonical_locale`, и
заполняются:

- переведённое имя;
- переведённое описание;
- статус текста.

Статусы означают:

- «Оригинал» — выбранный язык совпадает с языком источника;
- «Нет перевода» — записи ещё нет;
- «Машинный черновик» — backfill создал текст, но человек его не подтвердил;
- «Устаревший машинный» — источник изменился, машинный текст можно пересчитать;
- «Нужна проверка» — источник изменился после ручного перевода;
- «Проверен» — перевод актуален и подтверждён.

Машинный текст не становится подтверждённым автоматически. Кнопка «Подтвердить»
доступна для машинного черновика. Если перевода на язык интерфейса нет, в
отображении используется исходное имя; это не отключает распознавание и поиск.
Переводы не являются aliases и не должны использоваться для добавления форм
запроса.

### Проверка запроса

«Проверить запрос» работает только по сохранённому справочнику. Несохранённые
правки имени, alias, флагов и переводов в preview не участвуют.

Результат показывает:

- статус расширения (`no_match`, `applied`, `limited` и другие состояния);
- исходный и дополненный dense-запрос;
- формы, добавленные в sparse/BM25;
- распознанные термины и фактические совпавшие формы;
- причины пропуска, если сработали лимиты.

Preview не запускает ответ LLM и не изменяет документы или индексы.

## Seed

`backend/seeds/glossary.json` — версионируемый транспорт начальных записей.
Проверка без записи:

```powershell
cd backend
python scripts/seed_glossary.py
```

Применение отсутствующих записей:

```powershell
python scripts/seed_glossary.py --apply
```

Команда идемпотентна, не перезаписывает изменённый термин и не включает обратно
отключённый. При конфликте исходных полей запись не применяется; исправления
делаются явно через UI с новой audit-записью. Seed не запускается автоматически
при старте приложения или миграции.

## Корпусная приёмка

Перед включением расширения запускайте off/on на одном и том же корпусе:

```powershell
cd backend
python scripts/probe_sources.py --glossary-mode off `
  --cases scripts/glossary-probe-cases.json `
  --output scripts/probe-stage8-off.json
python scripts/probe_sources.py --glossary-mode on `
  --cases scripts/glossary-probe-cases.json `
  --output scripts/probe-stage8-on.json `
  --compare scripts/probe-stage8-off.json
python scripts/probe_sources.py --check-locales
```

Матрица содержит не менее 40 размеченных запросов и все legacy-сценарии.
Результаты сохраняют raw-кандидатов и итоговые блоки с полными
`doc_id`/`slug`/`chunk_index`, а сравнение отделяет реальное исчезновение
группы источника от выхода из top-k. `--compare` завершает работу с ошибкой при
полной потере источника или провале ожидаемого positive/negative-кейса.
Порог включения из плана: 0 ложных авторасширений, 0 нарушений фильтров,
принятые recall/precision и не более 10% дополнительной retrieval-задержки.
До такого решения `GLOSSARY_QUERY_EXPANSION_ENABLED` остаётся `false`.
При выключенном флаге `/settings` сообщает это состояние интерфейсу: чат
показывает, что глоссарий не участвует в поиске, и блокирует локальный
переключатель; та же информация отображается на странице администрирования.

## Rollback

До корпусной приёмки флаг `GLOSSARY_QUERY_EXPANSION_ENABLED` должен оставаться
`false`. Для отката выключите флаг и перезапустите backend либо отключите
ошибочный термин в карточке. Таблицы, переводы и история поиска сохраняются;
переиндексация документов не нужна.

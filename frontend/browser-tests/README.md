# Проверка источников чата в браузере

Fixture использует реальные ChatMessageView, ChatSources, ChatAnswer и composer.
Все источники синтетические. Она не входит в маршруты приложения: скрипт
создаёт отдельную копию frontend и устанавливает маршрут только там.

Из корня репозитория, PowerShell:

```powershell
node scripts/prepare-chat-ui-acceptance.mjs
$acceptanceDir = (Resolve-Path backend/.tmp-search-perf/history-ui-acceptance).Path
New-Item -ItemType Junction -Path "$acceptanceDir/node_modules" -Target "$PWD/frontend/node_modules"
Set-Location $acceptanceDir
node node_modules/next/dist/bin/next build --webpack
node node_modules/next/dist/bin/next start -H 127.0.0.1 -p 16303
```

Повторный запуск требует нового каталога — передайте путь вторым аргументом
скрипта. Старые измерения не перезаписываются. Linux/macOS: вместо Junction
используйте `ln -s` к существующему frontend/node_modules. Обычный SSO остаётся
действующим; backend должен быть запущен. Не изменяйте авторизацию для проверки.

Откройте http://localhost:16303/chat-ui-acceptance и нажмите **Run checks**.
Ожидается PASS: все 500 ссылок, выбор последней строки после закрытия/открытия,
цитата, 10 сообщений с раскрытым последним списком, полное раскрытие старого
списка, сохранение ручного раскрытия после нового ответа.

Для сравнения первого показа установите Sources=200, Messages=10. Перед каждым
Load sources нажмите Clear sources. Чередуйте Baseline all lists и обычный
режим не менее 30 раз. Console prefix `chat-ui-acceptance` содержит commit,
sources_paint и longtask. Baseline раскрывает все списки; обычный режим использует
тот же код и данные с раскрытием последнего. Время sources_paint — от setMessages
до второго requestAnimationFrame, не аппаратный timestamp экрана. Не запускайте
параллельно тяжёлые тесты. Сохраняйте обе серии, включая превышения порога.

Для ввода используйте нижний composer: input_paint измеряется тем же способом.
Кнопка 100 deltas проверяет обновление активного ответа. Дополнительно в настоящем
`/chat` проверяйте: fast/full → остановка → новый documents-запрос; старый список
и выбор сохранены, остановленный ответ не продолжает обновляться. Fixture не
заменяет HTTP/SSO-проверку этого сценария. Проверьте Tab от checkbox последнего
источника до его ссылки, переход к цитате и возврат в чат.

## Автоматический сценарий настоящего ChatPanel

В той же отдельной сборке откройте `/chat-panel-acceptance` и нажмите
**Run ChatPanel checks** после загрузки настроек. Сценарий работает с настоящими
ChatPanel, ChatProvider, api.js и NDJSON-парсером. SSO, `/auth/me`, настройки,
справочники и остальные запросы используют действующий backend.

Только запросы `/api/chat/stream` и `/api/chat/attempts/{id}/cancel` на время
сценария заменены локальным транспортом с синтетическими данными. Поэтому
проверка воспроизводима, не вызывает LLM и не создаёт историю в БД. Это
интеграционная проверка frontend; поведение HTTP-прокси и отмену на backend
продолжает проверять отдельный настоящий HTTP/SSO-сценарий.

Ожидается PASS по 25 проверкам: fast с 500 источниками и выбором №500;
остановка и отмена правильного attempt/session; новый documents-запрос;
запоздалые delta/sources/progress/result первого запроса; окончательный текст
и источники второго ответа; полное раскрытие прежнего списка с сохранённым
выбором; full с 167 источниками, ручное сворачивание и повторное раскрытие.
В сообщениях сохраняются все 867 источников. Транспорт специально допускает
события после AbortSignal, чтобы проверить защиту контроллера от старых ответов.

После PASS нажмите **Open normal chat**, вернитесь кнопкой браузера и нажмите
**Check history after returning**. Ожидается `navigation: PASS`: шесть сообщений,
старый вручную раскрытый список и выбор №500 сохранены. Основной чат в другой
вкладке остаётся независимым. Повторный Run очищает только текущий чат этой
вкладки. Результат доступен в `data-testid="panel-report"`, копии отчёта — в
console с префиксом `chat-panel-acceptance` и sessionStorage этой вкладки.
Каждый завершённый прогон содержит `completed_at` (UTC). После перезагрузки
или возврата восстановленный отчёт отмечен **«Предыдущий результат»**.
Новый Run убирает эту отметку; проверка возврата сохраняет время исходного
прогона. Старый отчёт без времени не получает вымышленную дату.

Маршруты `/chat-ui-acceptance` и `/chat-panel-acceptance`, а также profiling
устанавливаются только скриптом в отдельную копию. Они отсутствуют в обычной
production-сборке приложения.
